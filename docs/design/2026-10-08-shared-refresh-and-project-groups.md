# 多标签页共享刷新与项目会话列表方案

日期：2026-10-08。状态：统一刷新与按确认图实施的项目列表界面均已完成，独立审阅、完整测试和构建通过；尚未发布或重启生产服务。设计和计划由主会话完成，产品实现交给 gpt-6.1-sol/high 子 agent。

## 现状与目标

`AccountUsageProvider` 在每个标签页挂载、获得焦点、可见性变化以及每分钟定时读取用量，额度到期还会请求强制刷新。后端已有 30 秒缓存和在途合并，但普通读取在命中缓存前仍调用原生账户身份接口。多标签页因此有重复读取的确定路径。

左侧列表在每个标签页获得焦点、恢复可见、网络恢复、会话完成或改名时读取 `/api/sessions`；待释放状态还有每 5 秒轮询。`Runtime.list` 仅合并同时发生的原生读取，没有完成后的共享快照。列表 API 还要补隐藏过滤、元数据和已知分支，缓存应覆盖最终响应，而不只缓存一页原生数据。

目标是同一个 Web 后端维护统一状态和定时刷新。浏览器读取共享快照并订阅更新；增加标签页不会按标签页数量增加原生用量或列表周期查询。单个会话的消息流、占用检测和断线恢复维持现有机制，不把它们混入全局列表刷新。

## 后台刷新

- 复用现有鉴权、AccountUsage、Runtime、API 和 SSE 写入/过期关闭机制，增加全局状态更新通知。会话页面沿用消息 SSE 同时接收全局更新；首页和设置页使用独立全局 SSE，每个标签页正常只保持一个长连接。断线重连读取当前快照，焦点变化不强制调用原生接口。这样避免给每个会话页叠加第二条长连接；HTTP/1.1 的浏览器连接上限对多个标签页尤其明显。[MDN SSE 说明](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)
- 后端每 60 秒统一刷新用量和正在查看的列表查询。有有效全局订阅时运行一个调度器；全部订阅关闭后停止周期工作。首次读取填充快照，同时请求共享同一个在途任务；显式“刷新”仍可要求后端更新。
- 用量快照使用现有账户代际校验。账户变化立即废弃旧账户快照，并通知界面清除旧账户数据；确认重置机会、提交重置及结果待核实的原有账户校验和持久幂等逻辑保持。
- 列表共享缓存按排序、归档、隐藏开关、搜索词和分页游标完整隔离，缓存最终 API 响应。近期使用的查询参与周期刷新；缓存数量和闲置生命周期有界，不无限缓存所有搜索词。未知或失效游标仍返回原错误，不猜测分页位置。
- 创建、分支、名称、归档、隐藏、收藏和释放状态变化在后端使相关列表状态失效，短暂合并后刷新；普通消息 token 不触发全列表查询。其它客户端的变化由原生通知和每分钟刷新补齐。
- 共享任务由后端持有，单个浏览器取消或断开不取消其它标签页共用的读取；服务关闭时清理定时器、监听器和在途工作。不增加推理、后台会话、依赖或设置项。
- 失败时保留有明确成功时间的旧快照并显示更新失败/待更新；账户身份无法确认时不暴露旧账户数据。失败不会触发前端循环重试或并行刷新风暴。浏览器上的倒计时仅用于显示，不触发原生查询。
- 自动更新读取全部已加载分页的共享快照并合并，保留已加载的较旧会话；手动“刷新”沿用现有重置第一页的行为。请求仍受查询身份和序号保护，过滤切换后的旧响应不会覆盖新结果。

## MCP 进程数量只读核验

2026-10-08 17:41:57，真实 Developer 用户下观察到 16 个 `codebase-memory-mcp.exe`：15 个直接由同一 `codex app-server` PID 28136 创建，1 个为其中 MCP PID 6696 创建的内部 daemon。该 AppServer 的父 node PID 23088 在本机 3000 端口监听；这一批不属于 VSCode、标题隔离探针或测试进程父链。真实配置只有一个 codebase-memory-mcp 配置项。

Web 创建并复用一个 Runtime/AppServer，浏览器标签页和列表查询没有各自创建 AppServer。按 live PID 的实际可执行文件只读执行 `--version`，确认其为 `codex-cli 0.160.1`，与标题隔离探针相同；VSCode 扩展的另一份 bundled CLI 为 0.162.0-alpha.2，不能混用版本假设。

精确 tag `rust-v0.160.1` 的 Session 源码为每个已加载线程创建 `McpRuntime`，普通线程主动连接配置中启用的 MCP；子 agent 可根据缓存延迟连接，但实际使用工具时仍可持有自己的连接。复用已经运行的同一线程不会每次重建；正常一轮完成也不等于 Session 关闭。[Session 初始化](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/session/session.rs#L1574-L1577)、[线程启动策略](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/session/mcp_runtime.rs#L357-L360)

`thread/unsubscribe` 只取消订阅；无订阅且线程不活跃后才延迟卸载，0.160.1 默认 60 秒。用户配置没有显式覆盖这个值，实际宿主是否另有启动覆盖尚未验证。线程真正关闭时源码会 shutdown MCP 并终止 stdio 子进程，因此不能仅凭进程多判定缺清理。[取消订阅](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/request_processors/thread_processor.rs#L1020-L1045)、[该版本默认值](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/config/mod.rs#L3911-L3912)、[Session 关闭](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/session/handlers.rs#L314-L318)

当前 PID 尚未逐一对应到原生线程或子 agent，无法判定 15 个客户端中是否有泄漏。新标题的临时线程也未禁用继承的 `mcp_servers`，禁止模型用工具和关闭 plugins/apps 不会禁止用户手工配置的 stdio MCP 启动；这是一处可收窄的额外启动点，但新标题尚未部署，不能用于解释当前进程数量。此调查没有新建用户线程、发推理、修改配置或终止进程，后续进程生命周期改动须另行明确范围。
