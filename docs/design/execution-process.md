# 执行过程折叠设计

用户确认：先落文档再实施。将连续的思考与工具步骤合并成默认折叠的执行过程；降低嵌套展开的操作负担。

## 展示与分组

2026-09-22 用户验收后修订：接入原生 `item/reasoning/summaryPartAdded`、`summaryTextDelta` 和 `textDelta`，按步骤 ID、段落索引及文本偏移向浏览器增量同步，复用现有序号去重与断线恢复。只展示接口提供的文本；没有文本时用紧凑的“未提供摘要”状态，不反复创建“暂无摘要”正文占位。完整终态仍以原生记录为准，不补写未返回的历史摘要。`subAgentActivity` 默认直接显示 Agent 名称及启动/交互/完成/中断动作；路径、会话 ID 和原始 JSON 放入“原始数据”详情，不猜测子 Agent 的任务或结果，也不额外读取子会话。实施结果见[修订验收](../verification/2026-09-22-compact-input-reasoning.md)。

- 在每轮内按原始顺序归并连续思考、命令、工具和子 Agent 活动。`subAgentActivity` 属于执行步骤，不打断分组；子 Agent 与命令交错时统一放入一个默认折叠的“执行过程”。用户消息、助手正文（含进度说明和最终回答）及其他非执行项打断分组，不跨轮、不重新排序。未知类型沿用原展示，避免误隐藏交互。
- 折叠摘要显示“执行中 / 执行过程 · N 个步骤 · 当前动作或结果”。运行中同样默认折叠，不随新输出或完成自动开合。
- 展开后使用紧凑步骤列表，没有内层大边框卡片。思考摘要、命令名称、状态直接显示；短思考直接显示，长思考及完整工具内容使用“查看详情”，命令使用“查看输出”。各项可同时展开。
- 命令运行中也只由用户打开。默认行仅显示命令摘要，展开输出时显示完整命令和原文输出，并复用现有大输出按需请求、缓存、错误重试。非零退出码仍如实显示，不直接等同于整个任务失败。

## 状态和可访问性

- 分组以轮次 ID 和首项 ID 为稳定标识；增量追加、加载更早历史、终态更新不重置展开状态。
- 外层关闭只隐藏已有内容，不卸载内层，重开后保留已打开步骤、输出缓存和内部滚动位置。首次外层展开才挂载步骤，避免折叠历史创建大量正文节点。
- 外层使用原生 details/summary；内层使用带 aria-expanded、aria-controls 的文字按钮和 hidden 内容区域。键盘可操作，父层收起后内层不进入焦点顺序。命令完整内容可以在详情中阅读，不依赖悬浮提示。
- 审批、待回答问题、会话错误、轮次失败提示留在外层之外；折叠不会阻挡必要操作。切换会话后重新进入默认折叠，本轮不增加持久化偏好。
