# 全屏文件预览：正文阅读列与宽表格

日期：2026-10-11。状态：已按用户授权实施，主目录 `dist` 已更新。范围：现有全屏 Markdown 文件预览的有限布局调整。

## 用户目标与现状

用户需要阅读中文技术文档，并查看超宽表格。变更前全屏预览把整个 `.markdown-message` 一起放宽到 960 / 1440 / 1920px，表格获得了空间，标题、段落和列表也随之拉长。本次反馈截图显示正文横跨大片屏幕，读完一行后寻找下一行更费劲。

首轮分宽使用约 520px 正文列，用户实际阅读后反馈仍然太窄，明确要求至少恢复第一版宽度。本轮将正文上限恢复到第一版的 960px，保留表格单独扩展到 1440 / 1920px。

采用 Product Design 的上下文与研究方法，以本次反馈、现有组件和官方设计系统为依据。没有其他用户的频率数据，不将这次反馈泛化为群体结论。保持现有深色样式、字号、行距、工具栏和预览操作。

## 业界依据与取舍

- [NHS Layout：Reading width](https://service-manual.nhs.uk/design-system/styles/layout)：在流式宽容器内给正文单独设置阅读宽度，避免正文行过长。这直接支持“宽容器内的窄正文”结构。
- [GOV.UK Layout](https://design-system.service.gov.uk/styles/layout/)：正文列通常限制在约 75 个字符以内，内容需要时允许更宽的页面容器。
- [W3C SC 1.4.8：Visual Presentation](https://www.w3.org/WAI/WCAG21/Understanding/visual-presentation.html)：AAA 级视觉呈现要求提供不超过 80 个字符、CJK 不超过 40 个字形的行宽机制。首轮参考了其中的中文行长，最终宽度按用户的技术文档阅读反馈恢复为 960px；本方案不构成对整个产品 AAA 合规的声明。
- [USWDS Table](https://designsystem.digital.gov/components/table/)：多列表格在小屏可使用局部横向滚动；滚动容器需要能被键盘聚焦和操作。
- [MDN CSS 字体相对单位](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Values_and_units/Numeric_data_types)：`ic` 以字体中“水”的字形宽度为依据，`ch` 以“0”的字形宽度为依据。两者都只是字体度量，不能保证混合内容的精确字符数。

| 方案 | 阅读与表格效果 | 取舍 |
| --- | --- | --- |
| **推荐：居中的正文阅读列，表格向两侧扩展** | 文字控制行长，宽表格保留空间 | 同一页有两种宽度，需验证阅读位置与嵌套块 |
| 整篇统一收窄 | 正文易读，表格频繁横向滚动 | 无法充分利用已有宽屏档位 |
| 增加阅读 / 宽表模式切换 | 用户可自行选择整篇宽度 | 文本与表格交替出现时需要反复操作 |

## 推荐布局

正文阅读列居中，文字在列内左对齐。标题、段落、列表、引用、分隔线和文末操作采用同一列，形成稳定的左侧阅读起点。列表的缩进和编号包含在列宽中，嵌套内容不重复居中或缩窄。

正文列采用 `min(100%,960px)`，达到可用宽度时恢复第一版的 960px，窄屏随可用区域收缩。标题沿用同一列宽，不再按字体单位把正文限制到约 520px。中文、英文和中英混排共用规则，不做逐段语言检测，也不增加宽度切换选项。

独立的顶层表格以同一页面中心线向两侧扩展，保留当前宽屏上限。小表格至少占正文列宽度，较宽表格按内容增加宽度，最多达到当前档位；避免所有短表格都被强制撑到 1920px。超过上限的内容只在该表格内部横向滚动，页面保持单一纵向滚动。

| 视口宽度 | 正文 | 顶层表格可用宽度上限 |
| --- | --- | --- |
| 小于 1440px | 不超过阅读列与可用区域 | 不超过可用区域与 960px |
| 1440–1919px | 同上，不随屏幕继续拉长 | 不超过可用区域与 1440px |
| 1920px 及以上 | 同上 | 不超过可用区域与 1920px |

手机继续沿用 12px 内边距和安全区处理，正文在可用宽度内自然排版，表格保持列关系并局部横向滚动。桌面沿用 24px 内边距。长路径和内联代码可换行，正文不产生横向滚动。

列表或引用中的嵌套表格保留父块的缩进和语义，在父块内滚动；本轮不将整个列表或引用拉宽。Markdown 代码块跟随阅读列，保留已有的内部横向滚动和复制操作。独立图片、图表可用宽容器，沿用已有的适配与查看工具。源码模式、Git 差异、普通面板和聊天消息不应用本次全屏正文限宽规则。

## 实施落点与性能

已有 `Markdown` 渲染器使用 Streamdown 2.6.0；表格已经具备 `[data-streamdown="table-wrapper"]` 和局部滚动结构。实测顶层块位于 `.markdown-message` 的第一个 `div` 内，文末操作是第二个子元素。新增 CSS 仅在 `.preview-shell:modal` 下把容器和顶层块设为 Grid，标题、段落及操作使用居中阅读轨道，独立表格跨越全部轨道。嵌套表格不匹配跨轨道规则，仍受列表或引用的宽度约束。

正文宽度统一以 960px 为上限，受可用区域约束。表格包装层使用 `width:fit-content`，最小宽度为同一个阅读列，最大宽度由原有容器限制。复用 Streamdown 的语义、块样式和滚动节点，不复制正文、重新解析 Markdown、改变组件 key 或使用负外边距。

`PreviewShell.change` 原先在 Markdown 左侧加约 40px 的位置进行有限命中检测，正文居中后该点可能落在空白处。本次将横坐标改为 Markdown 与滚动视口交集的中心，继续使用原有的六个纵向采样、`preventScroll` 和位置校正。正文和表格区域均验证阅读位置保持。

不新增状态、依赖、逐帧测量或对每段内容的遍历。由 CSS 处理窗口缩放；展开 / 收起沿用已有节点与请求。安装版本的表格滚动节点没有 `tabindex`，因此在 `Markdown` 原有初始化 effect 中，仅对文件预览里的现有表格滚动节点补 `tabIndex=0`。键盘焦点轮廓向内偏移，避免被外层表格裁切；聊天消息不增加 Tab 入口。

1. 在 390、844、1280、1440、1920、2048、3440px 检查正文列、标题对齐和表格档位；正文不再随大屏无限拉长。
2. 用中文长文、英文长文、中英混排和长内联路径检查实际行长、断行、编号与 200% 浏览器缩放。

6. 用 Tab / Shift+Tab 和方向键操作表格；回归鼠标 / 触屏 / 键盘切换、Esc 无残留绿框，以及最近文件 / 全屏 / 手机抽屉的关闭层级。

8. 通过受影响浏览器回归、类型检查与构建后再更新 `dist`，记录实测结果和未验证范围。
