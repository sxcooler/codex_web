# Git 子仓库日志与原生会话标题修改方案

日期：2026-10-08。状态：两项功能已实施并验收，标题按用户选择使用 Luna/low。界面图为设计参考，实际实现沿用现有组件。

本次补齐两项能力：在 Git 日志中选择项目内的子仓库，以及在 Web 新建会话时根据任务生成 Codex 原生标题。沿用现有 Git 查询、模型连接、会话占用检测和原生命名接口，不增加依赖、模型设置或另一套自动标题存储。

- 仓库选择只作用于“Git 日志”。“变更”和“文件”继续读取会话关联的项目工作区。

- 保留现有图线、提交时间顺序、100 条分页、分支筛选、图片预览和 fetch 限制，不重做 Git Graph。

## 仓库发现和接口

当前 `Projects.gitLog`、`gitCommit`、`gitCommitDiff` 和历史图片读取均使用会话绑定项目的根路径。现有接口没有子仓库参数，因此必须统一扩展这条读取链，不能只在前端增加选择框。

新增只读接口 `GET /api/sessions/:id/git/repositories`，返回主仓库、已声明的子模块以及项目内普通嵌套仓库。使用现有鉴权和会话到项目的服务端绑定，不接受浏览器传入任意 cwd、Git 参数或绝对路径。

| 接口 | 修改 |
| --- | --- |
| `GET .../git/log` | 增加可选 `repository` 相对路径；分支列表随所选仓库返回 |
| `GET .../git/commit` | 提交及父提交从所选仓库读取 |
| `GET .../git/commit/diff` | 文件差异和图片版本元数据从所选仓库读取 |
| `GET .../files/image` | 历史图片的 revision 读取携带同一仓库参数；普通文件图片仍按项目读取 |
| `POST .../git/fetch` | 请求体增加可选 `repository`；原空请求体继续代表主仓库 |

仓库发现以 `.gitmodules` 和 Git index 中的 gitlink 补充子模块信息，以 `.git` 文件或目录发现普通嵌套仓库。候选目录必须经 Git 确认为自身的工作树根，普通子目录不能通过向上搜索伪装成另一仓库。

目录扫描跳过 `.git`、`node_modules`、`.local` 和现有敏感目录，不跟随 junction 或 symlink。内置扫描边界为深度 12、最多访问 20000 个目录、最多返回 200 个仓库、发现阶段最多 5 秒；达到边界返回“仓库扫描不完整”提示，不把截断结果表述为全部仓库。这些是内部保护，不增加设置项。

每次查询重新核验相对路径和目录实址，拒绝绝对路径、路径穿越和项目外工作树。允许 `.git` 为文件，以兼容子模块和工作树；其元数据目标只允许位于项目内，或属于已绑定主仓库的合法 Git 元数据关系。目录浏览的 `allowProjectDirectoryLinks` 不放宽仓库选择边界。

日志列表、详情、差异及图片的缓存键均包含仓库身份；分页游标也绑定仓库。fetch 去重使用实际所选仓库路径。继续保留现有 Git argv 调用、超时、输出大小限制和错误处理。

## 新建会话使用原生标题

验证截图保存在隔离测试记录中，不随公开源码分发。

自动标题只在 Web 新建会话的流程中发起一次。继续已有会话、打开或恢复会话、后续发送消息和导入历史都不触发；已有名称保留。重复提交同一创建请求沿用现有 `clientRequestId` 幂等结果，不重复生成。

生成期间以原生 preview 或“未命名会话”作临时显示，任务执行不等待标题。生成成功后写入原生 `thread.name`，侧栏、会话顶栏和浏览器标题同步更新；重新打开或由 VSCode 读取时，得到同一个原生名称。图中的“命名中”仅表示当前创建流程的短暂状态，不增加持久化标题状态表。

新建请求不再把提示词前 80 字符保存为最终 Web 标题。现有 `web_title` 只保留旧数据和既有行为的兼容性，自动摘要不写入该字段，不增加标题来源列或另一份自动名称。

没有可总结文本的空白或纯附件创建请求跳过自动标题，保留原生临时显示；后续发送消息不补触发。标题根据任务文本总结，与任务语言一致，最多 36 个字符，不带多行说明。仅生成标题，不增加任务描述功能。

## VSCode 自动标题的实际链路

核对对象为本机已安装的官方扩展 `openai.chatgpt-26.1002.51308-win32-x64`。该版本的自动标题最终保存为原生名称，但生成由扩展主动发起，并不是普通 `thread/start` 自动完成命名。

```text
VSCode 新建会话
  → threadMetadataGeneration.generateTitle
  → 临时 thread/start，ephemeral=true
  → turn/start 生成结构化标题
  → 发起 thread/unsubscribe 清理临时会话，返回标题结果
  → thread/name/set 写入原生名称
  → thread/name/updated 更新界面
```

| 本机扩展源文件 | 核对到的行为 |
| --- | --- |
| `webview/assets/app-initial-bb656fdae302.js:233–234` | `Jhn/Khn` 调用标题生成桥接，收到结果后调用 `setThreadTitle`；新建回调受 `skipAutoTitleGeneration` 控制 |
| `out/extension.js:618` | `R2` 创建 ephemeral thread，执行生成 turn；返回结果前在 finally 中发起 unsubscribe，不等待其完成 |
| `out/extension.js:1075` | `B4e/$4e` 生成并校验标题，使用 30 秒超时 |
| `webview/assets/app-initial-f98e01875506.js:1806` | 标题写入在客户端排队，并检查预期标题；临时提示词名称可以仅保留在界面中 |
| `webview/assets/app-initial-f98e01875506.js:1820–1821` | 新建会话触发自动命名，持久化调用 `thread/name/set` |
| `webview/assets/app-initial-f98e01875506.js:1810` | 接收 `thread/name/updated` 并更新原生名称和界面标题 |

该扩展还会给部分未命名历史线程补标题，本次只采用新建触发路径。扩展内部默认使用 `gpt-5.6-luna` 和 low effort；本项目按用户明确选择，标题生成使用 `gpt-6-luna + low`。主任务继续使用用户选定的模型和思考强度。当前 CLI 的原生模型列表已确认 `gpt-6-luna` 支持 `low`，不会替换为扩展的旧型号。

原生名称由 `thread/name/set` 设置，名称变化通过 `thread/name/updated` 通知，并在后续 thread 读取中返回。[OpenAI 官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)

## Web 生成和写回流程

1. 在 `Runtime.create` 的幂等创建流程中，取得主线程 ID 并接受首轮任务后，后台发起一次标题生成；生成只读取创建时的任务文本，输入上限沿用 VSCode 的 2000 字符。
2. 使用现有 app-server 连接创建独立 ephemeral thread，通过结构化输出获取 `{title}`。标题专用模型为 `gpt-6-luna`、思考强度为 `low`，保留创建时的 provider 和现有账户连接；主任务的模型和思考强度不受影响。不增加模型设置、外部 API 或新认证。每个符合条件的新建会话增加一次短摘要推理。
3. 临时请求使用只读权限，关闭与标题无关的 hooks、multi-agent、plugins 和 web search。临时请求不会执行原任务，相关事件由生成请求单独消费，不出现在主会话记录或最近会话列表。
4. 生成完成且主线程仍属于本次新建流程、尚未设置名称时，调用现有 `Runtime.rename` 写入原生标题。与 Web 手动改名共用线程内执行次序，写入前检查名称，保留已观察到的原生名称。自动命名不增加独立的跨客户端标题存储或锁管理系统；现有命名 RPC 没有条件更新参数，不承诺跨客户端原子防覆盖。
5. 将命名纳入现有占用和释放顺序：释放前收束为已写回或已取消，避免交接后还有延迟写入。当前 `rename` 本身只是命名 RPC，新建流程负责这一时序，不把“已有轮次占用检测”误写成 `rename` 已有的条件更新接口。
6. 补齐 `Runtime.onNotification` 对 `thread/name/updated` 的处理，沿用既有 `change(kind: name)` 和前端增量同步。
7. 生成失败或 120 秒超时保留原生 preview，清理临时会话；原任务继续执行，不循环重试。生成与启动排队共用此时限，清理另有受限收尾。原生命名结果未确认时先读回核对，不盲目重放写入。

`ephemeral` 表示临时会话不持久化，不等于完全禁止文件读取；只读权限也不等于禁用全部工具。实现需核对当前独立 CLI 0.160.1 接受的字段和配置，不能把扩展所用私有字段原样发送给不同版本。使用受支持的原生 thread 和 turn 接口完成生成，不依赖 VSCode 私有二进制或未公开的桥接方法。
