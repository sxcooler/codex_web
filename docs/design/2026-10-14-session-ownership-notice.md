# 会话权限核对提示只在异常未解决时显示

日期：2026-10-14。用户确认沿用正常流程保持安静、实际异常保留提示与恢复入口的规则，并要求先落文档再实施。

## 原因与显示规则

会话页尚未取得快照时，前端也将状态表示为 `UNKNOWN`。原提示只判断这个状态，因此正常初次加载、前台核对或快照同步期间，可能短暂显示「当前只读查看，执行权限待确认」和「接续会话」。

复用已有快照、核对和读取状态决定提示，不增加延时、定时器或网络请求。

| 情况 | 输入区提示 | 顶部状态 |
| --- | --- | --- |
| 尚未取得快照，或正在前台核对、读取快照 | 不显示权限待确认提示及接续按钮 | 沿用核对／同步状态 |
| 核对结束，最新快照仍为 `UNKNOWN`，且没有单独的读取或接续错误 | 显示原提示和「接续会话」 | 待核实 |
| 明确接续后正在核对占用 | 沿用现有接续进度反馈 | 核对中 |
| 同步失败、接续失败、其他客户端占用 | 保留现有异常及处理入口，避免同时叠加泛化的权限待确认提示 | 沿用实际状态 |
| 核对后可继续 | 不显示权限待确认提示 | 沿用空闲／历史浏览／运行状态 |

展开与收起输入区使用同一条权限提示规则。收起时实际未解决的 `UNKNOWN` 显示摘要和「查看详情」；展开后保留接续入口。提示继续使用既有浮层，不改变输入区、聊天区尺寸和阅读位置。

## 实施边界

- 仅调整 `SessionView` 的提示选择；不修改自动同步、原生 writer、接续、发送、审批、释放及重试期限。
- 正常只读加载、核对和提示显示不产生会话写入；按钮仍须用户明确点击。
- 沿用 [历史浏览提示清理](2026-10-13-session-actions-cleanup.md) 与 [自动释放反馈](2026-10-13-automatic-release-feedback.md) 的规则，保留历史验收记录。
