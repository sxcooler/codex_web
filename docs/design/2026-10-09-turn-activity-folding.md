# 整轮执行过程折叠方案（已实施，待统一部署）

## 对照结论

官方截图在一轮任务完成后只展开最终答复，前面的说明、思考和工具操作统一放入“用时 34m 14s”的折叠区。Web 截图则把每段工具操作分别折叠，工具之间的说明消息仍展开。

差异出在 `src/web/Conversation.tsx`：`TurnMessages` 只把 `stepLabels` 内的工具/思考项当作执行过程，`agentMessage` 无论 `phase` 是 `commentary`、`final_answer` 还是未知，都会作为独立正文并打断分组。折叠摘要也未读取整轮耗时。Runtime 的消息投影和前端 SSE 合并保留原生 phase；仅收到文本 delta 时，phase 暂时未知，之后的完整 item 可以补齐。

旧 `tests/execution-process.html` 明确要求“正文进度保持可见”和多个过程分组，说明此前实现和验收采用了工具折叠的口径，未对齐官方的整轮过程折叠。没有读取截图对应的 SampleSDK 会话正文，因此不声称其具体 phase 已实测。

## 拟定界面

正常完成的一轮：用户输入 → 默认收起的一条过程摘要 → 最终答复。展开摘要后，按原顺序展示中间说明、思考、命令、文件修改、MCP 和协作步骤。正文里的文件链接、图片预览、复制及必要操作沿用原消息组件。

按用户 2026-10-09 补充截图修正：运行中展示中间说明与工具过程；转为完成、失败或中断终态时自动收起过程，只留最终答复或终态说明。审批、需要回答的问题和未处理的异步问题继续显式显示，不能因为折叠而隐藏交互入口。

终态自动收起只发生一次；此后用户手动展开的选择，不被后续 SSE 或 phase 补齐重置。运行中也可手动折叠或展开。未展开的过程不提前读取延迟加载的命令全文。

原型：[交互示意](2026-10-09-turn-activity-folding.html)。页面中的文本和耗时是示例，不是真实会话数据。

## 消息归类与边界

| 原生记录 | 显示位置 |
| --- | --- |
| `agentMessage.phase=commentary` | 过程折叠区 |
| `agentMessage.phase=final_answer` | 外部正文，多个 final item 全部保留原顺序 |
| 思考、工具、命令、计划、文件修改、协作活动 | 过程折叠区 |
| 用户插话、审批、需要回答的问题 | 显式显示，维持原时间顺序 |
| 生成图片等直接交付的结果 | 保留可见的结果与操作，不因归为过程而隐藏交付物 |

正常一轮只有一个过程区；遇到用户插话、交互项或多个最终答复等边界时允许分段，不能为了合成一个区把用户输入和结果重新排序。整轮耗时只在首个过程摘要标注，分段不重复声称相同耗时。

旧记录的 phase 缺失时：终态轮次至少保留最后一条普通助手消息在外部，避免把唯一答复收进去；其余普通助手消息归入过程。有明确 final 的记录以原生 phase 为准。运行中的未知消息不能仅因“当前最后一条”就当成最终答复，摘要显示其进度，全文仍可展开。失败或中断且无 final 时保留最后一条助手说明并显示真实终态。

耗时优先采用原生 `durationMs`，其次采用有效的整轮开始/完成时间。运行中用有效开始时间展示已用时间；缺失或无效时间不补造时长。消息时间、轮次时间的毫秒/秒单位必须分别处理。

## 实施范围与验收

主要修改 `Conversation.tsx` 的归类、分组和摘要，以及已有过程折叠样式；复用 Message、Markdown、审批、图片和延迟命令输出组件。无需新增后端摘要请求、原生会话、模型调用或重新写历史。

验收覆盖：

- 完成轮次只有最终答复展开，正常轮次只有一个默认收起的过程区；展开后的说明和工具顺序不丢失。
- 明确 commentary/final、多个 final、旧 phase 缺失、失败/中断无 final、只有最终答复的记录。
- item started/delta/completed 的 phase 补齐、历史分页和流式更新，不丢文本、不打断用户展开状态。
- 用户插话、审批和异步问题始终可操作；过程中的链接、图片、复制及命令输出加载继续有效。
- 桌面及 390px 布局、键盘展开、耗时单位和缺失时间。

## 实施与验证记录

已按运行中展示、终态收起的最新补充实施。整轮终态仅自动收起一次，手动展开和通知定位的选择在 phase 补齐、分段合并时保留；显式展开优先，之后对整组手动收起可覆盖旧展开选择。
