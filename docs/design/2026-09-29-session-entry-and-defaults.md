# 会话入口、模型默认值与新任务首屏

## 目标

- 最近会话使用真正的链接，普通点击保持页内切换，浏览器的中键、修饰键和右键菜单保持原生行为。
- 新任务模型与推理强度每个值只出现一次；“上一次”表示最近一次成功新建任务所用值。只在新建任务时回写 Codex 用户级配置，会话内改选只作用于下一条消息。
- 新任务创建已获确认后，即使原生历史暂不可读，也不把已提交的首条消息伪装为未提交，更不自动重发。

## 行为

1. 会话标题改为指向 `/sessions/:id` 的链接，操作菜单独立。归档条目恢复前不开放导航。当前链接设置 `aria-current="page"`。
2. 首页选择一个模型时，推理强度改为该模型支持的默认值；用户可再明确选择其他支持的强度。创建请求仍显式传所选值。创建成功后，Web 通过受限接口原子写入用户级 `model` 与 `model_reasoning_effort`，重新读取并核对结果；写入失败不撤销已创建的任务，而是在会话页提示。项目级配置可能覆盖用户级配置，界面以实际生效值为准，不谎报项目配置已改变。
3. 最近一次成功新建任务的模型和强度由首页在创建确认时记录，不再由任意已打开会话的快照覆盖。会话输入区的选项保留原有单轮覆盖语义，不写用户级配置。
4. 创建确认含 threadId 和首轮状态。首页将已确认提交的首条消息带到会话页；历史确认后按 clientRequestId 去重。历史未确认时显示“已提交，正在同步”，禁用重复发送。
5. 原生 `thread/turns/list` 明确不支持时，服务端改用 `thread/read(includeTurns: true)` 获取权威轮次；状态核对采用同一兼容方式。其他错误继续按原错误处理，短暂元数据未写入仍使用既有有限重试，不添加固定等待。完整读取超过协议帧限制时明确提示，不截断历史。

## 验收

- 桌面和手机的普通点击、中键/新标签页、菜单操作与当前项状态正确。
- 同名配置选项不重复；“上一次”仅随成功新建任务更新；会话内选择不回写；模型切换后强度始终有效；原生写入失败和项目覆盖可见。
- 使用缺少轮次分页的原生实现，新任务有首条消息时仍可读取与核对；临时不可读不重复提交，恢复后只显示一条消息。
- 生产构建、专项回归和当前 Codex CLI 实测通过后，核对运行服务已加载新版本。

## 实施验证

- `npm run build` 通过；运行时与浏览器专项分别通过 95 项和 11 项。
- Codex CLI 0.156.1 在隔离的 `CODEX_HOME` 中完成 `config/batchWrite` → `config/read` 往返，未触碰用户真实配置。
- 完整 Node 套件串行运行 267 项中 262 项通过、5 项按平台跳过；并行运行中既有的 80 毫秒 RPC 超时测试曾受负载影响，单独复测也通过。
- 现有托管服务的 `prepare-update` 两次返回 409（运行时仍有活动或未释放工作），因此尚未重启；须在服务准许更新后核对线上版本。
