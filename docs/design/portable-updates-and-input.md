# 便携更新、自启动、提问与模型目录

2026-09-23 用户确认方案并授权落文档、实施。基线 `67d5d59`；不修改已发布的 0.1.5，不重启承载当前工作的服务，不自动升级独立 Codex CLI。

## 确认的设计

- Windows 自启动使用当前用户入口，名称 `codex_web`、图标由现有 Logo 生成。优先验证原生快捷方式在任务管理器中的显示；若无法可靠显示，使用包含文件描述和图标的轻量启动器。安装/卸载只迁移本目录的旧 Run 项，保留其他安装；安装根目录固定以便更新。
- 发布完整包和应用更新包。应用更新包包含全部应用文件，不包含 Node、node_modules 和用户数据，不做二进制差分。平台及运行环境文件散列组成兼容指纹；指纹不匹配要求完整包。更新入口离线接收下载包，校验、暂存、拒绝活动任务、正常停止、备份替换、验证启动；失败恢复应用文件。`.local`、账户、原生历史和工作目录不覆盖。更新中断有记录可恢复。数据格式不兼容时不能宣称代码回滚等于数据回滚。
- 原生异步提问来自 `agentMessage.delivery=async` 和 `questions`，原地显示选项与自由输入，显式发送，复用原生消息/插话。同步请求仍走原生 respond；允许自由输入时仍显示可点选选项。普通 Markdown 列表不猜测为问题。提交 ID 与问题消息 ID 关联，结果未知不重发，确认成功才标已回答。原轮次完成不等于异步提问失效；跨客户端占用保留原有保护。
- 模型刷新绕过 Web 五分钟缓存重新 `model/list`，不假造模型、不切换当前选择。设置显示 CLI 来源、版本与目录读取时间；安全重载原生进程只在无活动任务/请求时允许，CLI 升级仍独立操作。

## 实施与验收

1. 提问：复用原生结构，后端校验问题来源并记录回答，前端点选/输入；验证同步与异步、插话、历史、重复提交、超时、多设备和重启。
2. 模型：强制读取和安全重载，保留失败时旧目录与选中项；验证并发、缓存、运行中拒绝重载。
3. 自启动：生成 ICO、带名称入口、迁移/卸载归属检查；验证 PowerShell 5.1/7、路径含空格、已有启动项和便携布局。
4. 更新：扩展清单和打包，离线更新/恢复与启动互斥；验证 Windows/Linux 的升级、淘汰文件、篡改/不兼容包、用户文件保留、启动失败回滚及中断恢复。
5. 全量测试、浏览器桌面/手机检查、生产构建、独立包验证、整体审查；所有本次提交最终合为一个中文提交。

## 证据与限制

用户提供的会话原生记录确认 `request_user_input_async` 已产生带问题结构的异步 AgentMessage。旧 Web 渲染遗漏 questions；同步表单 `isOther` 分支也将选项降为文字。旧模型缓存为五分钟，独立 CLI 与 VS Code 插件版本不同。0.1.5 Windows 归档应用文件压缩体积约 5.7 MiB，运行环境约 85.5 MiB；新更新包尺寸以实际构建为准。

实施结果和未完成的实际设备验收在本文件追加，不把模拟测试当成任务管理器或登录自启的视觉验收。

## 实施结果

- 自启动直接使用带文件描述和图标资源的轻量 EXE，由系统 .NET 编译器生成，调用原有隐藏后台启动入口。未先对快捷方式做任务管理器视觉验证，因此这里是工程选择，不是宣称快捷方式已验证失败。PowerShell 5.1/7、含空格路径、真实启动转发与返回码、文件描述/图标提取、旧项迁移/卸载保护均已自动检查；任务管理器实际显示与下次登录启动仍需设备验收。
- 提问复用两套不同的原生结构：同步请求用 question/options 对象，异步 AgentMessage 用 title/options 字符串。回答状态进入现有元数据数据库；历史分页也核对未知提交，防止已确认回答长期锁在待核实。没有改写原生历史或猜测普通列表。
- 模型可强制刷新；重载只在空闲时执行。读取失败保留旧展示目录并标记过期，发送前的模型能力校验仍要求有效目录。设置显示独立 CLI 路径、初始化返回的版本信息、最后成功读取时间；不自动修改 CLI 或账户配置。
- 更新包包含完整应用文件，候选 Windows/Linux 更新 ZIP 约 5.8 MiB，完整包约 95/97 MiB。两个平台均已实测原 0.1.5 停止状态升级、全新完整包启动/登录、在线空闲升级与配置/认证保留。候选产物存放于隔离目录，不替换已发布 0.1.5。
- 更新采用原子硬链接锁，要求 NTFS/ext4 等支持硬链接的文件系统；FAT32/exFAT 使用完整包迁移。保留区独立恢复入口可在安装目录中的更新脚本被截断后使用；最终记录写入失败保留恢复记录。启动失败回滚、历史文件淘汰、错误散列/路径/运行环境和中断恢复由回归检查覆盖。

最终全量检查 Windows 257 项（252 通过、5 跳过）、Linux 257 项（250 通过、7 跳过），均无失败；10 项桌面/手机浏览器回归、生产构建与两平台最终候选包的启动/登录/在线更新检查通过。独立审查无剩余实质问题，独立针对性回归 86/86 通过。测试期间发现并修复 Windows 测试进程已退出时的清理竞态。
