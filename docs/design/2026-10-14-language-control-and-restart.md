# 语言控件样式与任务空闲重启

2026-10-14。用户指出设置页语言选择框样式问题，并要求今后界面修改均经过浏览器验证；同时确认后台列表读取不应阻碍重启，没有运行中的 Codex 任务即可重启。

## 界面

语言选择在设置页沿用相邻设置项的标签、下拉框间距、普通字重与箭头内边距。桌面空间足够时标签和控件并列，窄容器允许换行且保留间距；键盘焦点轮廓不能碰到标签。登录页保留既有纵向布局。

只修复控件在不同入口的样式，不改语言解析、偏好存储、同步和请求行为。在旧实现上以真实组件浏览器断言复现，修复后核对 390/1440px、中英文、200% CSS zoom、键盘焦点和切换交互，并查看截图。

## 重启

- 设置页预检、延迟重启的最终检查以及“重启 Codex”使用一致的任务判断。
- 列表、历史、文件等只读查询不构成活动任务，不要求等待后台轮询结束；关闭过程中允许这些读取收到断连或运行时切换错误。
- 正在提交任务/写入、运行任务、待审批、待输入，以及无法可靠确认的原生状态仍拒绝重启。继续检查所有原生已加载线程，不只看 Web 当前页。
- 保留原生查询 20 秒期限、游标和返回值校验、epoch/实例一致性与关闭期限；不加自动重试、不强杀受管服务。
- 原严格空闲检查仍用于更新器和自动空闲释放。仅显式重启放宽只读操作，写入提交计数在 finally 中释放。
- Web 服务在最终核对通过后同步关闭新请求入口，避免核对后出现新的任务启动；“重启 Codex”关闭自身原生实例并让读取恢复到新 epoch。

1. 先保存本说明与项目浏览器验证规则。
2. 增加真实 Runtime fixture 回归：挂起后台列表/历史读取时可预检和准备 Web 重启；原生重启可以关闭读取；写入、审批/输入、未知活动与核对期间出现的新任务仍拒绝。
3. 增加语言控件浏览器回归，在旧样式上确认失败，再改局部样式。
4. 运行 Runtime/标题/重启/更新器定向回归、浏览器回归、类型及生产构建，并独立审查。
5. 更新前端静态资源时保留旧资源，逐个核对哈希与真实 HTTP 入口。后端必须成功重启才生效，本次不自动重试此前失败的重启。
