## 排版与查看图片

所有直接过程记录使用同一行容器：上下内边距各 12px，文字行高 23px，分隔线与文字起点对齐。长消息自然增加高度，不为凑齐高度截断正文。展开内容统一与摘要相隔 12px；内部工具详情沿用相同文本样式。去掉上一版的彩色告警底板、状态圆点和装饰标签，退出码只用轻微颜色区分。

“查看图片”默认是一条与其他记录对齐的可展开行：`查看图片 · readback-01.png`，不重复标注“已完成”、分析结论或进度百分比。展开后显示项目内可预览的图片、原路径和既有“在新标签页预览”操作；图片约束宽度、保持比例，窄屏不横向溢出。多张记录按原顺序保留，不新增图片墙或轮播。

这是原生 `imageView` 的过程动作，计划纳入整轮过程，但自身保留独立摘要，不能埋进“命令、思考”一行；完成后随整轮收起。当前产品 `ViewedImage` 本来已经支持这条摘要与按需预览，但 `turnActivity` 尚未把 imageView 纳入过程。实施时复用现有组件与文件访问边界，不能仅改 CSS 而漏掉完成后的折叠。

图片路径不保证可预览：项目外路径、外部 URL 只显示现有路径文字，不自动请求；缺少路径显示“图片路径未提供”。浏览器当前预览失败显示“图片预览不可用”，不能把它解释为模型当时查看失败。原生 imageView 不保证 status，字段不足时保留中性标题。

明确的 `imageGeneration` 是交付结果，继续显示独立图片卡片；用户附件继续留在用户消息里。MCP/动态工具附图沿用真实工具名称与既有图片操作，不能仅凭 imagePreviews 判定成“查看”或“生成”。

## 建议方案

继续使用整轮过程容器。运行中容器默认展开，按原始顺序交错显示助手进度说明与折叠的工具记录；完成、失败或中止时仍只自动收起一次，最终答复或终态说明在外部。用户手动展开、收起和通知定位的行为沿用已有规则。

“有意义”按原生 item 类型和状态确定，不对正文做长度筛选或语义猜测：

| 内容 | 运行中的默认展示 |
| --- | --- |
| 助手 commentary 或 phase 尚未补齐的普通说明 | 显示原文 Markdown、链接和附件，不另做摘要 |
| 当前活动 | 容器标题显示“正在思考 / 正在运行命令 / 等待审批”等真实状态；不再逐条铺开空白思考 |
| 连续的命令、工具调用、思考、文件修改和协作记录 | 合并成就地的“执行记录 · N 项”折叠行；不跨越说明、用户插话或交付物重新排序 |
| 原生 imageView 查看图片 | 独立可展开行显示文件名，预览默认收起；完成后随整轮过程收起 |
| 有摘要的思考、计划、命令全文、输出、原始工具参数 | 可展开执行记录查看；默认不与进度正文竞争空间 |
| 子 Agent 活动 | 计入执行记录；运行状态可在摘要中显示活动数量，具体名称、启动、完成事件在展开后保留 |
| 仅退出码为 1 的命令 | 归入连续执行记录，默认不单独占行，包括原生将非零退出标为 `failed` 的命令；展开仍显示原命令、输出、退出码 1 和原始数据，不改写成成功 |
| 工具失败、其他非零退出、拒绝或中断 | 相关行在运行过程内显式可见，全文输出仍按需展开；退出码 1 同时带有独立 `error`、`isError`、`result.isError` 或 `success:false` 时也保持独立显示；拒绝、中止与没有退出码 1 的失败状态保持显式 |
| 审批、用户提问、异步待答问题和用户插话 | 保持显式可见与可操作，不放入机械记录折叠行 |
| 生成图片等直接交付的结果 | 保持结果预览与操作可见；沿用既有分组边界 |

每段连续机械记录只产生一个摘要；除仅退出码为 1 的命令外，有异常标记的工具打断该段，单独显示状态与可展开详情，然后再开始下一段。无内容 reasoning 仍计入数量，展开后可查看原始记录，不伪造思考摘要。“展开”后复用现有命令/工具详情组件，输出继续延迟读取。当前未完成的工具在折叠摘要上可见，避免用户以为任务没有活动。

整轮“项过程”继续计算原始过程 items，折叠段的数量是它包含的 items 数；状态条是同一活动的显示，不额外计数。原型的计数仅演示位置，不用于验收计数正确性。原型没有实现真实审批、SSE 或通知点击，相关规则须在产品实施时验证。

## 实施范围与回归

修改点集中在 `src/web/Conversation.tsx` 的 `ExecutionGroup`/`Step`/`ViewedImage`、`src/web/turnActivity.ts` 的显示分组，以及既有过程样式。复用 `ImagePreview` 与既有文件访问校验；将原生 imageView 纳入整轮过程，imageGeneration 保留交付位置。`Message` 的文件链接、附件、复制、图片和询问操作保持使用现有组件。后端、原生 RPC、订阅及通知发送逻辑不属于本界面修改范围。

通知定位 `revealItemId/revealToken` 必须同时展开整轮过程及目标所在的内部执行记录；保留 `data-item-id`、`data-turn-id` 和焦点目标。终态自动收起不能覆盖通知定位或用户之后的手动展开。

实施口径：只有默认运行展开的组在终态自动收起；明确手动开合与通知定位优先。运行中已经定位的同一目标在终态保留当时的开合选择，用户后续收起的组不会被同一定位 token 或 SSE 补齐重新打开。

用户同时确认修复通知 URL 的残留定位参数。定位成功、已穷尽未找到或明确失败后，以 replaceState 消费本次目标；等待登录、快照、旧历史及 SSE 时保留。保留其他查询参数、hash 和 history.state，不新增导航或会话 API，旧异步定位不能清除新通知。清 URL 不取消当次高亮与已展开目标。

必要验收：连续机械记录合并但不跨说明；空白 reasoning 不逐条占位；真实工具异常和等待交互显式可见；运行转终态只收起一次；手动展开和 SSE 补齐稳定；通知可以定位到被内部折叠的目标；未展开不读取命令全文；查看图片默认收起、按需加载、路径边界、缺失与预览失败提示、不虚构查看状态；imageGeneration 和用户附件不误入过程；桌面与 390px 窄屏、键盘操作及既有消息操作回归。
