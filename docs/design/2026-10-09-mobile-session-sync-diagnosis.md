## 已验证的代码机制

1. `SharedClientState.changed` 将 status、release、thread、resync 和轮次状态变化均作为硬失效：版本递增并清空成功缓存。读取过程中版本改变会重读一次；再次变化就返回上述 503。随后普通读取在 60 秒失败缓存内可立即复用错误，主动刷新才绕过该失败缓存。
2. `associated → saveMeta` 每次读取会话快照都调用 `metadata.save` 并无条件失效所有共享列表；即使只更新打开时间、项目和标题不变也是如此。fork 快照还另有无条件失效。多标签页恢复或快照刷新会增加与列表读取相撞的机会；现场尚没有事件关联日志来确认某一次碰撞的具体来源。
3. Runtime 接收到完全相同的两条原生 idle status 通知仍产生两条 status change。`Runtime.status()` 探测和 `Runtime.list()` 本身不是已确认的失效触发者，不能把探测请求直接当通知来源。
4. 前端列表读取和共享层总期限均为 30 秒；浏览器计时开始得更早且还包含传输，慢读取有两种错误先后竞争的风险。此风险是源码事实，不是本次手机“读取超时”的已证实原因。
5. 会话页 focus/pageshow/online/visibilitychange 会重新检查当前会话。现有 EventSource 仍存在且 status 返回 `resync:false` 时，不主动读取左侧列表；旧列表错误可能保留。真正重连得到 SSE ready 会间接触发列表刷新，不能说完全没有恢复链路。关闭提示只是隐藏该次提醒，下一次 sessions 事件失败可以再次显示。

隔离验证不操作真实会话或启动原生 Codex：

- `.local/mobile-session-diagnosis/diagnose.mjs` / `summary.json` / `run.txt`：五组 status/turn/release 连续失效都让两次成功加载最终返回 503（不足 2ms），普通读取复用同一失败；完全相同 status 通知重复产生 change。
- 同脚本确认隐藏和归档后的失败不能返回失效前的旧列表。不能为了减少报错取消这一保护；turn 会影响最近顺序，release 会影响释放状态，也不能简单删除这些刷新。
- `.local/mobile-session-diagnosis/run-1791549397191/result.json`：真实 Chrome、真实隔离 SSE 服务，1280px 与 390px 均确认仅恢复焦点不刷新列表、旧错误保留；SSE 真正断开重连的 ready 会刷新，手动刷新能恢复，50 个共享事件合并为在途请求及一次待刷新。390px 是桌面 Chrome 的窄视口，没有冒充真机锁屏验证。
- 浏览器超时提示的隔离检查把期限缩放至 200ms，只验证现有错误处理与恢复；该数值和耗时不是手机现场证据。

## 最小修订范围（已确认）

- 元数据只在影响列表的数据真的改变时做硬失效。重复保存打开时间、未变化的项目关联和已知 fork 不应让在途列表作废；沿用现有路径比较与标题优先规则。
- 区分列表成员、可见性、归档、标题/搜索条件等硬变化与运行态刷新。运行态变化合并为待刷新，在当前读取完成后再更新，避免连续通知把两次正常读取都作废；仍更新排序和释放状态。隐藏/归档等硬变化继续清除旧缓存并拒绝旧结果。
- 页面从后台恢复到前台时，合并触发一次现有共享列表读取，取消已失效的浏览器读取；不新增前端定时轮询或每个标签页独立拉原生数据。成功后清除旧错误，真正失败保留提示。保留 SSE ready 的恢复路径，并避免 focus/pageshow/online 同时触发重复刷新。
- 核对前后端总期限，使浏览器有接收后端结构化结果的余量；补最少诊断字段关联共享读取、失效类别及页面恢复，禁止记录请求正文、搜索内容或凭证。用新证据继续核对尚未归因的读取超时，不将延长期限当作版本冲突修复。

界面沿用现有列表和提示，没有新增控件或视觉布局；本轮不需要另画界面图。实施验收将覆盖重复快照、并发状态通知、多标签页/后台恢复、事件合并、成功清错，以及隐藏、归档、排序、释放状态和游标安全。新增修复完成后再按用户要求单独取得本次重启许可。

## 实施合同

- 后端共享读取总期限仍为 30 秒，仅列表的浏览器总期限改为 40 秒。其他会话读取、提交和 API 期限不变。
- 软刷新保留成功缓存和硬版本，合并消费 dirty；新状态在在途读取完成后再刷新。硬失效仍清除旧缓存、推进版本并保护隐藏/归档结果。软事件不能清除已有失败冷却，避免客户端共同重试放大原生读取。
- 前台恢复走已有共享缓存读取，保留每页身份与列表筛选状态；恢复来源 query 字段限定为 `foreground / stream-ready / shared-update / manual`，不参与共享缓存键。后台停止浏览器列表读取并合并更新需求，不新增轮询。
- 诊断关联仅含内部 entryId/readId、Fastify requestId、版本、固定失效类别/结果和上述恢复来源；不记录 raw query、搜索内容、User-Agent、正文或凭证。已有常规异常日志保持，诊断写失败不能影响业务。
- 子 agent 分别实施共享层、元数据/API、前端与浏览器夹具；主会话负责集成审查、完整 Node 回归、隔离构建与最终编译页面验收，最后整理为一个中文提交。

## 实施结果与验收

重复快照保存仍持久化打开时间，但项目和有效 Web 标题未变化时不再使列表失效。已知 fork 的运行状态不推进硬版本；更新时间和最近顺序变化走软刷新，新 fork、名称、项目、可见性和归档等变化继续硬失效。连续软通知只标记待刷新，当前正常读取可完成，随后合并更新；失败冷却与隐藏/归档后的旧结果保护均保留。

列表在页面隐藏时取消浏览器请求，保留已加载内容；恢复前台、离线后恢复或仍有错误时合并读取现有共享状态，成功后清除提示。连续可见且健康的焦点事件不触发额外读取。另修复前台恢复请求与 SSE 更新重叠时，重复 focus 覆盖待更新来源并吞掉后续刷新的竞态。分页、搜索条件、项目折叠和“更多”数量保留；没有增加前端轮询或依赖。

新增诊断记录可用 HTTP requestId 对应共享 entryId/readId，区分缓存、加入在途读取、软/硬失效和最终结果；恢复来源只记录上述固定枚举。常规异常日志保持。此次现场的版本冲突已复现并覆盖修复；截图中另一次“读取超时”的确切请求仍未归因。
