# 功能链路性能审计（2026-09-20）

目的：主动检查小操作触发全量读取、逐文件串行子进程、重复请求、无界缓存和重复渲染。沿实际 API、原生 RPC、磁盘/Git 与浏览器调用链定位；修复根因，不通过放宽超时掩盖问题。

## 审计范围

| 功能 | 检查内容与结论 |
| --- | --- |
| 最近会话、归档/隐藏、项目列表 | 原生列表使用状态数据库，不读取对话正文；检查筛选分页、并发与前端刷新 |
| 打开、发送/插话、审批、中止、自动/手动释放 | 打开/恢复排除轮次；发送幂等与模型/权限校验保留；释放的完整历史依赖已修复 |
| 历史、SSE、状态核对、完整输出 | 保留最近 20 轮、按需输出、64 KiB 回放和 256 KiB SSE 背压边界；检查旧版历史回退 |
| 文件/目录/Markdown/图片与 Git | 文件接口的快照依赖已在 `d63cd7d` 修复；继续检查 Git 批量统计、单文件差异、旧请求和阅读缓存 |
| JUnit 报告 | 改为目标轮次内的命令校验，移除整段历史依赖 |
| 用量与重置 | 并发读取合并、30 秒缓存；账户身份前后校验及重置幂等持久化属于必要校验，保留 |
| 图片与附件 | 原生缩略图缓存 64 张/4 MiB，2 个处理通道、32 个任务上限；上传流式落盘且有大小/数量/配额约束 |
| 通知、认证、静态资源 | 通知由生命周期事件触发，不读取快照；密码计算异步且限并发；gzip 异步，静态资源带指纹缓存；Service Worker 不缓存 API |

## 已验证的根因与修改

### 释放会话误读全部历史

`release()` 原来通过完整 `readThread()` 校验空闲状态，使导航离开也读取命令输出和图片。改为只读取会话/轮次状态头，仍保留进行中轮次、待审批、原生状态及事务锁检查。不能以减少读取为由直接取消订阅。

同一长会话的状态头读取本机测得 **428 ms、17 轮、0 个 item**；上一轮完整快照实测 **9192 ms**。本次仅执行只读探针，没有对真实会话执行释放或恢复。

### 导入报告误读全部历史

前端将 `turnId` 和 `commandItemId` 一并发送；服务端通过原生 `readItem` 在指定会话/轮次内查找命令，不信任客户端传入的命令对象。JUnit 文件路径、安全检查、大小限制和过期判断保留。其他轮次/会话的命令不能被借用；缺少轮次返回参数错误。

### 同步状态头先复制正文再丢弃

`threadHeader()` 原来先 `structuredClone(thread)` 再去掉 `turns`，使大图片/输出也进入临时副本。现在先剔除 `turns`，仅复制需要保存的头信息，保持内部对象隔离。

32 MiB 合成正文的 5 次平均测量：旧操作 **12 ms**，新操作 **0.013 ms**。这是该函数的本机微基准，不是端到端速度承诺；回归检查确保不会遍历被剔除的 item。

### Git 列表为每个文件读取 patch、重复解析提交

提交详情原来逐文件读取完整 patch、逐路径启动 `cat-file`，单文件预览又重复读取整个提交详情。工作区列表也逐文件启动 `git diff --numstat`。

改成批量读取 NUL 分隔的 raw/numstat；单文件预览只读 raw 元数据校验文件，再读取所选 patch。提交解析合并成一次 `git show`，不需要分支列表的接口也不再额外读取当前分支。目录枚举只解析一次项目根目录，仍逐项验证链接与越界。

20 个变更文件的本机测量：

| 操作 | 优化前 | 优化后 |
| --- | --- | --- |
| 提交详情 | 65 个 Git 进程 / 2719 ms | 3 个 / 140 ms |
| 单文件差异 | 70 个 / 2867 ms | 3 个 / 138 ms |
| 工作区列表 | 22 个 / 944 ms | 3 个 / 146 ms |

保留进程数量回归，防止重新引入逐文件进程；不对墙钟时间做脆弱断言。覆盖重命名、二进制、根提交、合并父提交、特殊路径、超过 5 MiB 的无关文件，以及以 `++` / `--` 开头的源码行计数。文件与目录互换时按全部路径的祖先关系校验，避免目录 pathspec 把隐藏的敏感文件包含在 patch 中；同名前缀的兄弟路径不能绕过检查。

### 旧会话按需读取仍遍历无关完整轮次

不支持 `thread/items/list` 的旧会话原来从最近轮次开始逐轮读取全文，直到找到目标。现在较早历史页、命令输出和图片先用 `itemsView:notLoaded` 定位，再仅读取目标轮次的 full 内容，并核对返回的轮次 ID。原生不透明游标在只读探针中验证可跨 itemsView 和 limit 使用，不自行推算游标。

同一长会话较早命令的本机只读实测：**9386 ms / 17 次 full** → **1648 ms / 共 3 次调用、其中 1 次 full**，目标轮次和命令 ID 一致。25 轮模拟会话中，较早的 5 轮页面从 25 次 full 降至 5 次；找不到的轮次不读取正文，游标重复或目标漂移会拒绝结果。

### 用户已切走，服务器仍继续读取历史

快照及历史分页把 HTTP 响应连接断开传为 `AbortSignal`，每次原生分页返回后检查取消，停止调度剩余页。取消后不写入同步基线，并清理快照监听与读取计数。新旧两种原生读取路径及真实 HTTP 断连都有回归。

已经发给原生的单次 RPC 仍等它完成；不通过杀进程或取消原生任务来终止只读操作。

### 隐藏会话触发无界向后翻页

为了凑足可见会话，原实现可能在一次请求中翻完整个会话列表。现每次最多读取 5 页，保留原生 `nextCursor` 供“加载更多”继续；空页但仍有游标时提示“本页会话均已隐藏，可继续加载”。重复游标报错，避免循环。

### 前端重复读取、滚动更新与缓存累积

- 文件列表及预览切换时用 `AbortController` 取消过期读取，并阻止迟到结果覆盖当前资源。
- Git 提交详情及差异按会话、提交、父提交、文件与刷新版本复用；未变化的抽屉关闭再打开由 2 个额外请求降至 0。手动刷新仍重新验证，失败保留旧内容并提示错误。
- 文件列表、正文、错误以及 Git 详情/差异缓存各限制 20 条；淘汰后正常重读。不缓存登录凭据，不改变服务端实时工作目录和路径校验。
- 滚动位置存入 ref，停止滚动 50 ms 后写入存储，卸载时补写。布局恢复读取最新位置；不逐个滚动事件更新 React 状态。回归中 12 次滚动最多 2 次存储写入，Git 图表渲染计数不增加。
- 切换最近/归档及显示隐藏会话只重读会话列表，不再顺带重读项目列表。
- 顺带修复 Markdown 相对链接跳入多层目录时丢失 `/` 的问题。

## 验证原则与边界

- 各修复保留可运行回归，检查原生 RPC/请求数量及安全语义，不只检查最终页面能否显示。
- 性能数字注明样本和测量层级，不能把本机耗时当成跨网络耗时。
- 不重启当前生产后端、不终止 VS Code，不发送真实模型任务、不消费账户重置机会；使用独立原生只读连接、临时仓库及模拟浏览器接口。
- 生产后端需要重启才能应用后端改动；本次不覆盖已经发布的 0.1.4 安装包。
- 旧协议的近期窗口仍最多读取 20 轮正文；不支持从原生中途取消单个 RPC。超大单轮内容及磁盘负载仍可能增加等待。
- 前端缓存限制条目数，未新增精确字节计量；现有正文/差异响应上限继续生效。Git 图仍渲染用户已主动加载的记录，沿用最多 10000 条的上限，未引入虚拟列表。
- 构建通过，但既有按需 Markdown/语法语言包仍有大于 500 kB 的分块提示；本次没有扩大依赖或把语言包改成首屏同步加载。
