范围：扫描 `src/` 与 `scripts/` 的版本号判断、不支持判定、按钮禁用及错误恢复路径，复核匹配到的运行时、账户、模型、权限、历史和脚本逻辑。这是针对误拦截的检查，不是全库无缺陷保证。

## 已修复

- 重置只允许 `codex_remote_web/0.153.4`：升级到 0.156.1 会被禁用，即便重置接口契约仍兼容。已移除精确版本门槛，保留账户与机会核对。
- 重置首次调用前的账户变化、明确的接口不存在被包装成结果未知：会留下无须存在的待核实记录。现对确定未执行的新操作清理记录并返回原因；此前确实未知的操作仍保留幂等键。

## 本次继续修复

| 优先级 | 位置 | 触发与影响 | 建议 |
| --- | --- | --- | --- |
| 高 | `src/codex/runtime.ts` 的 `phase`、`open` | 已由 Web 加载、原生状态为 active，但当前轮次 ID 缺失时，被归为 EXTERNAL；重复 open 提前返回，不重新核对。内存模拟已确认，未发送原生 RPC。 | 区分原生正在运行与已确认的外部占用，并让刷新能够恢复当前轮次信息。不能直接放开所有 active 会话的写入。 |

Node 最低版本、更新包平台/指纹、认证文件格式、托管权限要求、未知审批类型校验都有实际数据或安全契约，未作为误拦截删除。

上述三项已实施：本 Web 已加载的 active 会话缺少轮次 ID 时先显示 UNKNOWN，刷新通过原生轮次头恢复唯一的 inProgress ID；已确认的外部 writer 不自动接管。协议生成和诊断取消 0.153.4 精确版本门槛，仍记录实际版本并校验协议响应、权限和操作互斥。

## 错误结束会话的恢复案例

- 用户反馈右上角“待核实”、不能发送、释放提示状态不对。原生存档最近一轮以 `usageLimitExceeded` 失败结束；未发现 JSON 损坏。只读窗口快照约 368ms、2.59MB，可正常获取历史。独立探针的 notLoaded 只表示探针自身未加载，不代表线上进程空闲。
- 代码确认存在相符的死路：systemError 一律映射 UNKNOWN 并禁止发送，open 对 loaded 提前返回，release 又只接受 idle/notLoaded。线上内存状态未直接采集，因此不把这条复现路径表述成完整现场抓包。
- [0.156.1 官方状态实现](https://github.com/openai/codex/blob/rust-v0.156.1/codex-rs/app-server/src/thread_status.rs) 的 `system_error_sets_idle_flag_until_next_turn` 测试明确：systemError 是持续至下一轮的错误标记，下一轮启动清除它。恢复无需 unsubscribe/resume；官方 unsubscribe 还存在卸载宽限期，不能假设立即卸载。
- 仅对本 Web 持有、没有活动轮次或待答交互、且原生轮次头均为终态的 systemError，核对后恢复 Web 操作状态；快照继续保留原生 status 和失败原因。刷新、释放复用同一判断。不发送真实任务、不调用额度重置、不关闭其他会话的进程。
- 新增回归覆盖错误结束后继续、释放、缺失轮次 ID 恢复，以及仍有工作或无法确认历史时不得卸载；其他活动会话与外部 writer 保持保护。
