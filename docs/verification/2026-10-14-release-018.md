# 0.1.8 发布验证

本版汇总 0.1.7 之后的项目归属、文件阅读、会话恢复、设置和 Git 工作区改进。Codex CLI 最低版本继续为可识别的稳定版本 **0.160.1**，便携 Node 继续固定 **24.20.0**。账户和 CLI 独立安装；测试不发送真实模型任务，不改日常配置，不重启日常服务。

## 用户可见变化

- 项目按原目录规则统一分组，自动注册到原生项目并维护历史会话归属；移除手动移入/移出及重复的目录分组入口。支持更多/收起，手动刷新恢复三条预览；选择器显示项目名称，保留内部标识以区分同名项目。
- 文件浮层全屏保留预览状态和阅读位置。正文保持阅读宽度，表格可单独扩展到宽屏；修复 Esc 焦点残留、工具栏间距、长路径挤占操作区，增加图标复制路径。文档全屏中的 Mermaid 全屏正常显示，并逐层退出。
- 只读查看不取得会话占用，回前台先核对状态；最近排序使用真实对话时间。改善新任务首次历史暂不可读、断线及未确认发送恢复，加载更早消息一次触发且保留已加载页面。
- sleep 等待步骤纳入执行过程，模型过载提示说明过去的中断。临时提醒采用浮层，移除正常自动释放及历史浏览的常驻提示；操作菜单移除无效工作目录切换。
- 设置只读详情与编辑动作分开。指令可取消并返回、保存并返回，未改动也能退出；失败保留草稿，未知保存结果先核对再重试。改善未保存导航保护、可见返回焦点及迟到响应处理。
- Git 日志支持子模块/嵌套仓库、远程分支和本地刷新后后台获取；改善原生标题、文件读取拥塞、跨浏览器同步、通知定位及 Windows 服务退出记录。

## 升级兼容与发布门槛

发布检查发现共享通知 helper 曾位于 `src/notificationTarget.ts`，0.1.7 更新器的应用白名单会拒绝此新路径。将原样 helper 放入已有 `src/codex/`，同步导入，沿用旧白名单和标准 Update 入口，不要求使用者手动补更新器。回归先复现白名单拒绝，再验证通过。

依赖锁文件除应用版本字段外不变。两平台必须从同一正式公开提交原生构建，核对新旧所有运行环境文件的 size/SHA-256 和 runtimeFingerprint；对新解压包验证登录、后台启停、同版应用更新，以及官方 0.1.7 完整包自身更新器到 0.1.8 的运行中更新、恢复运行状态和用户数据保留。只有这些实际结果均通过，才发布对应更新包。更早版本未在本轮验证直接升级。

五个归档及公开增量 Git 对象须复查白名单、个人环境/真实标识/凭据候选、manifest 提交与散列、Linux 执行权限；原始截图及本地证据目录不进入公开版本。最终五包 SHA-256、两平台安装/升级结果、正式提交和六个远端资产的核验记录随 [v0.1.8 发布页](https://github.com/sxcooler/codex_web/releases/tag/v0.1.8) 提供。不能用构建成功替代安装、升级或远端发布成功。
