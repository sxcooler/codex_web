## 后续补验：按平台组织部署脚本

- 入口拆分为 `scripts/windows/` 与 `scripts/linux/`，npm 的 TypeScript 入口路径保留。Windows 自启安装支持从原 `scripts/start-server.ps1` 迁移。
- Linux 在 WSL2 Ubuntu 22.04、Node 24.20.0、systemd 249 下通过三项部署回归：前台单实例与 PID 归属校验；真实用户 systemd 安装、启动、停止及子进程退出；Tailscale 配置保护和失败不覆盖 Web 配置。
- systemd 服务和测试以普通用户运行，独立临时目录包含空格、`%` 和 `$`；确认可选环境文件实际加载。测试结束清理临时服务和进程。验收期间临时启动已有用户管理器，未启用 linger。
- Windows 两项部署回归通过，覆盖稳定 PowerShell 入口、旧脚本目录迁移、服务进程树清理及无关 Node 保留。本机已有计划任务已迁移到新路径，保持运行，HTTPS 页面检查返回 200。
- Tailscale CLI 在 Linux 测试中为受控模拟；该 WSL 未安装 Tailscale，未验证真实 Linux Serve 或手机连接。不据此声明物理机重启或用户重新登录后的自动启动已通过。
- 可运行 `node --test tests/linux-service.test.ts`；真实 systemd 项须在有用户总线的 Linux 会话执行 `LINUX_SERVICE_TEST_SYSTEMD=1 node --test tests/linux-service.test.ts`。默认跳过此项，避免普通测试安装用户服务。

自动化测试覆盖发现已有 CLI、失效配置修复、默认手动安装、非交互拒绝安装、显式选择安装、取消/失败后重试、安装后重新检测，以及端口冲突不保存首次配置。安装器执行和交互输入使用受控模拟，未在现有 Windows 用户环境重新执行真实安装；真实产物烟测使用已安装的官方 CLI。不能据此声称外部安装器所有交互已端到端验证。

## 真实任务过程与验证边界

- 普通用户由用户授权创建，Codex 登录由用户自行完成；未复制 Windows 凭据。前期 root、未登录检查不作为最终通过依据。
- 一个专用 Thread 共进行五轮真实调用：首次报告验收脚本错误；修正后运行并插话成功；释放恢复后继续成功；运行中中止；新浏览器重开后再次完成。最终状态为四个 completed、一个 interrupted，无待审批项，并已释放原生运行时。
- 首次脚本只捕获 PermissionError，而 Linux 沙箱以 EROFS 拒绝越界写入；修正为接受 EACCES/EPERM/EROFS 后复验通过。这是验收脚本错误，本次补验未修改产品代码。
- 全新浏览器使用独立上下文，重新登录 Web 后验证持久历史和状态恢复；这项检查不证明跨浏览器上下文自动保留登录 cookie。
- 验收任务只操作专用合成项目；批准/拒绝等完整审批分支继续使用已有自动化回归，本轮真实任务未请求提权，也未验证模型联网权限。

不据 WSL 结果声明所有 Linux 发行版支持；macOS 未适配、未验证。本轮未生成 Linux 便携包，未重启原 Windows 服务；Windows 测试包仅用于验收，正式发布包需从最终交付版本重新生成。验证工具、日志和截图保持隔离，不进入源码包；保留真实测试产生的原生会话历史。
