# 紧凑输入、摘要同步与子 Agent 展示

2026-09-22，用户验收后明确确认修订。依据：[会话工作区](../design/session-workspace.md)、[执行过程](../design/execution-process.md)。

## 修正内容

- 摘要：原先只接收助手正文和命令输出的文本增量，遗漏原生 reasoning 的三个增量通知。现按步骤 ID、summary/content 段落索引及文本偏移同步，不每次传整份文本；浏览器去重、快照重叠合并、断线事件重放和终态权威覆盖沿用现有机制。对无效索引拒绝处理。
- 没有上游文本的思考项只在行内显示“未提供摘要”，不再额外渲染“暂无摘要”正文。不会补写历史摘要，也不推断未返回的思考内容。
- 子 Agent：默认显示路径末级名称和“启动／交互／完成／中断”，不把活动事件完成误当成子任务成功。完整路径、会话 ID 与原始对象仅在“原始数据”中查看；不额外请求子会话。
- 输入：展开和紧凑态始终共用同一个 textarea。紧凑态保留发送/插话、中止和展开按钮；手机回车换行，桌面沿用 Enter 发送及 Shift+Enter 换行，组字事件不发送。附件与模型等附加选项保持挂载但隐藏，上传继续；紧凑态不能新增粘贴/拖放附件。
- 草稿、模型设置、手动调整的展开高度、历史滚动和底部跟随保持原机制。附件未就绪、占用、待审批或提交结果未知时，紧凑态和展开态使用同一套发送禁用条件。异常和待处理入口仍可见。
