# 公开发布隐私检查

## 范围与结果

本次检查覆盖当前 Git 跟踪的文档、源码、脚本、测试、锁文件和静态资源，以及 `git rev-list --objects --all` 可达的提交、树清单和文件对象。检查项目包括个人用户名和绝对路径、设备与私网域名、项目名称、Thread/Turn 标识、邮箱、常见密钥格式及凭据赋值候选。

当前文件中的个人环境示例已泛化；测试中的会话标识使用合成 UUID，测试邮箱和固定测试密码只用于隔离 fixture。私网地址段判断、协议字段、依赖完整性散列和公共文档链接属于正常代码与依赖数据。检查没有发现已确认的真实 API 密钥或私钥。

`.local/`、原生 Codex 用户目录、认证文件、数据库、附件、日志、截图、测试输出和旧 `.git` 均不得进入发布物。忽略目录只核对排除规则，不读取、删除或迁移其中的凭据。运行包和源码包应按明确文件清单导出，打包后还需复查归档目录及文本内容。

## 原历史仍不可直接公开

旧 Git 对象和提交身份仍含个人环境记录。清理当前文件或 squash 本次提交不会移除祖先提交、其他分支及标签可达的内容；原仓库历史应继续留在本地。不要直接推送此仓库或把 `.git` 加入压缩包。

建议从经过检查、完全不含 `.git` 的干净源码包开始，在新目录初始化仓库，配置自己的提交身份后上传 GitHub。本次没有改写旧历史、删除本地数据、更改提交作者或执行推送。

## 限制

本次属于本地规则扫描和人工上下文核对，不能证明不存在任意格式的秘密。没有扫描远端仓库、reflog、不可达对象、无关用户数据或原生聊天历史；也未对二进制内容做 OCR 或隐写检查。新增文件、重新构建和新增依赖都可能改变发布内容，因此本说明不替代最终归档复查。私有明细仅保存在被忽略的本地审计报告中，公开报告不记录发现值。
