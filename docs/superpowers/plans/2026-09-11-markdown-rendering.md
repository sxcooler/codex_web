# Markdown 消息渲染设计与实施计划

日期：2026-09-11。状态：已实施并通过验收。

## 目标与范围

Codex 回复支持 Markdown，在生成中、历史回放和重新进入会话时保持一致的排版。用户消息保留原文和换行；命令输出、工具 JSON、文件 diff 与受控图片附件使用现有组件。原生历史仍保存原文，不修改后端协议。

选用 Streamdown 2.6.0 与 @streamdown/code 1.1.1，复用其 GFM、未闭合语法处理与 Shiki 高亮。无需引入 AI SDK、shadcn 或自行编写 Markdown 解析器。参考：https://github.com/vercel/streamdown 。

## 展示与交互

- 正文：标题、段落、列表、引用、加粗、删除线、行内代码、代码块、表格、任务列表与链接。
- 用户输入及乐观消息保持纯文本；不改变发送、插话或失败恢复行为。
- 代码块显示语言与一键复制，生成中使用纯文本、完成后启用语法高亮。未知语言降级为纯文本。代码不强制换行，长行仅在代码块内部横向滚动。
- 表格有表头、边框和清晰间距，窄屏在自身容器内横向滚动。
- 回复提供“复制 Markdown”，复制原文而非 DOM 文本；按钮报告成功或失败。代码复制保持原缩进。
- 文本更新复用已有 200ms 快照调度。根据所属 turn 与当前 activeTurnId 判定正在生成的消息，历史消息用静态解析。
- MarkdownMessage 只接收 text 和 streaming 两个基础值并 memo，避免每次快照都重新解析历史。异步高亮造成高度变化时也遵守现有跟随开关；向上阅读不被拉回底部。

## 安全、性能与样式

不解析原始 HTML，不执行脚本或嵌入页面。外链仅允许 http/https，使用新标签及 noopener/noreferrer；危险协议和本机路径不转成可执行链接。Markdown 图片不自动加载，现有鉴权附件显示保持原样。

保留库的清洗与加固处理，禁止通过自定义组件绕过链接过滤。高亮资源从本地构建产物加载；消息级错误边界覆盖顶层 Markdown 包及内部高亮子模块，加载或渲染失败时显示可选择复制的原文，不影响其他消息。首版不接 Mermaid、数学公式或代码运行功能。

Streamdown 与高亮组件通过动态 import 加载。高亮使用 JavaScript 正则引擎，无需放宽生产 CSP。生成中不执行高亮，避免为每个增量片段缓存 token；代码内容变化时重建 CodeBlock，隔离过期异步回调。当前高亮插件的缓存键仅取代码首尾和长度，可能将中部不同的代码误判为相同；统一核对 token 还原文本与本次原文，不匹配就显示纯文本，待上游修复缓存键后可移除这层保护。

Markdown 样式限定在消息正文，适配现有深色配色，覆盖当前全局 pre、code、white-space 和表单样式对排版的影响。任务复选框只读。避免全局样式改动影响工具面板。

## 文件与实施步骤

1. package.json / package-lock.json：安装并锁定上述两个直接依赖。
2. tests/markdown.html：按已有浏览器自检页面模式建立回归，覆盖基础格式、流式切片、安全链接/HTML/图片、用户原文、复制、移动端溢出及高亮缓存一致性；tests/send-message.html 覆盖真实消息组件的生成状态、长历史和滚动。
3. src/web/MarkdownMessage.tsx：集中 Streamdown 配置、代码高亮、安全组件及复制反馈；使用 memo 稳定历史渲染。
4. src/web/Conversation.tsx / SessionView.tsx：仅替换 agentMessage 正文并传入当前生成状态，复用现有 item.id 与滚动跟随。
5. src/web/style.css：加载必要库样式并追加隔离的 Markdown 样式。
6. 运行 npm test 与 npm run build，在浏览器打开 /tests/markdown.html，并重跑 /tests/send-message.html 验证没有破坏即时发送/插话。
7. 核对生产构建、本地静态资源和安全 CSP 兼容；更新本文验收记录；将本次全部变更记录为一个中文提交。

## 验收标准

中文混排及所有首版格式可读；半截代码围栏、加粗和链接不导致崩溃；完成后的显示与历史一致。代码与回复复制结果和原文相符。长代码/宽表格不撑破手机页面。脚本、原始 HTML、危险 URL 和远程图片不能执行或自动请求。历史更新不造成持续重复解析，用户向上滚动后不会被自动拉回底部。
