# 0.1.10 发布计划

> **For agentic workers:** 使用 superpowers:executing-plans 按项执行；两平台独立验收可以并行。

**Goal:** 发布可安装、可升级、内容已复查的 0.1.10。

**Architecture:** 沿用独立的公开脱敏 Git 历史，在同一冻结公开提交原生构建 Windows x64 与 Linux x64 glibc 产物。完整验收通过后上传草稿，再正式公开并匿名下载复核。

**Tech Stack:** Node 24.20.0、npm、Git、PowerShell、Bash、现有便携打包与验收脚本。

**Spec:** [发布指南](../../guides/publishing.md)、[便携包指南](../../guides/portable.md)。

## 约束

- Codex CLI 最低稳定版本 0.160.1，运行依赖锁定内容不变。
- 不推送私有开发历史，不打包用户数据、凭据、原始截图、本地证据或 WSL 验收环境。
- 不发送真实模型任务，不改日常配置，不重启日常服务。
- 中断、失败、跳过和未验证项目如实记录；旧版本结果不视为本版通过。

## 执行与检查

- [ ] 更新 package / lock 的版本、双语 README、便携包说明与发布验收文档；保留变更范围和已知限制。
- [ ] 从上次公开提交建立隔离目录，迁移本次当前代码与脱敏文档，复查差异及公开内容，冻结为单个中文提交。
- [ ] 两平台分别运行全量 Node 测试、类型检查、生产构建和原生便携打包；校验五个归档的清单、源码提交、执行权限、散列及指纹。
- [ ] 两平台验证全新解压包／自身更新、官方 0.1.9 原版入口升级，核对配置、认证、用户数据、外部文件与升级后登录。
- [ ] 运行受影响入口的浏览器回归，查看桌面／窄屏、中英文代表截图，保留实际覆盖范围。
- [ ] 复查新增公开 Git 对象及全部归档；合并五份资产散列，确保六个正式附件一致。
- [ ] 用正式 tag 和草稿 Release 上传全部资产，复核远端大小与 SHA-256 后公开；匿名检查 latest、校验文件和更新包实际下载。

## Review Focus

- 真实完成轮次与真实中止仍须区分；失败同步应可人工重试。
- 官方旧包的运行环境指纹、原始 Update 入口和配置保留必须实测。
- 公开父历史独立于开发历史；仅公开审计过的当前变化。
- 原始截图及私有环境信息不因文档迁移而重新引入。
- 发布说明仅涵盖本项目的变更与验收范围，服务商侧故障留在排障记录。

执行日志、失败记录、计数与散列保存在忽略目录；最终结果附正式发布页。
