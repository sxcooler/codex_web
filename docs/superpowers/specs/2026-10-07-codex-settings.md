# Codex 设置页设计规格

日期：2026-10-07。状态：P0 已实现，Task 1—8 验收与整分支审查通过；交付合并为一个中文提交，保留全部原临时提交信息。尚未部署。实际验收证据与限制见 [设置能力记录](../../verification/codex-settings-capabilities.md)。

## 1. 目标与已确认范围

让用户从 Codex Web 管理当前服务器主机的 Codex，能够回答：现在用什么配置、来自哪里、修改影响谁、何时生效、已安装哪些插件、额度与服务是否正常。

用户确认以常规、配置、个性化、使用情况、插件、电脑操控为功能分类；追加要求：**插件已安装列表纳入 P0，插件管理操作单独放 P1。** 后续明确授权已启动隔离工作树中的 P0 实施；真实账户配置／指令写入、插件授权、电脑操作和线上重启不在本轮授权范围。

| 阶段 | 范围 | 验收边界 |
| --- | --- | --- |
| P0 | 核心配置读写、使用情况页、精简常规、个人／项目指令、已安装插件列表 | 可独立交付；真实数据、错误可辨、保存可核对 |
| P1 | 原生记忆控制；插件详情、启停、授权、安装卸载与市场 | 每个模块先验证当前 CLI 能力，再补单独规格和计划 |
| 前置验证 | 电脑操控可行性：当前 Web 启动的原生进程能否发现桌面／浏览器工具 | 独立于 P0 发布；仅查看能力和连接状态，不改变访问授权 |
| P2 | 电脑操控管理、应用访问规则和浏览器连接管理；高级外观 | 前置验证通过并另行明确接口后实施 |

导航展示顺序为常规、配置、个性化、使用情况、插件。电脑操控尚无可交付能力时不放一个可点击的空页面，后续完成再加入。优先级决定实施次序，不要求照搬桌面端全部设置。

## 2. 实施前基础与复用点

- `src/web/main.tsx` 的 `Settings` 已有版本、目录、模型刷新、重启、诊断、通知、布局重置和密码修改；提取为独立页面，保留功能。
- `TurnOptions.tsx`、`turnSettings.ts` 已有模型／推理强度／权限选择与浏览器本地的新任务偏好；不能另造一套互相覆盖的默认值。
- 首页新任务创建成功后，除记录浏览器偏好，还会调用 `/api/model-defaults` → `Runtime.saveModelDefaults` 写入原生模型默认值。P0 保留这个既有行为，新配置页与此入口必须共享校验、冲突与回读规则；不能误称现有行为只写 localStorage。
- `AccountUsage.tsx` 的 provider、额度内容、手工重置确认和结果未知恢复，以及 `src/server/account-usage.ts` 已存在；页面与工具栏弹窗共享一份状态和请求。
- 原生协议缓存 `.local/protocol` 包含配置读取、原子写入、来源层、预期版本以及 `plugin/installed`。这是协议线索，不等于当前进程已支持；实现时通过只读探测验证。缓存不加入产品源码，也不编辑生成文件。
- 现有 graph 索引部分过时，以上结论已通过当前源文件核对。

## 3. 全局约束

1. 不新增生产依赖；复用 React、Fastify、Node 标准库和现有测试工具。
2. 首期只写用户级 Codex 配置；项目配置只显示来源和覆盖效果，不提供任意 TOML 编辑器。
3. 浏览器偏好、主机默认配置、项目有效配置、当前会话设置分别表达；不承诺一套简单优先级覆盖全部原生规则。
4. 设置页写操作显式保存；显示原值／新值及范围。保留首页创建成功后保存模型默认值的既有行为，并补齐版本保护。GET 不修改配置、不恢复会话、不安装插件、不重启进程。
5. 配置写入必须有版本检查和回读；禁止为“生效”自动重启或重发任务。
6. 管理路由复用登录、Origin、CSRF 校验；禁止接收任意文件路径、任意配置键或任意 RPC 方法。
7. 远程页面操作的是服务器主机；“此浏览器”设置只影响当前浏览器。缺失、受管、未知、失败不显示为关闭、零或未安装。
8. 兼容 Windows 主使用环境及现有便携包路径，保留其他平台代码路径；界面验证 390px 和 1440px，无横向溢出，表单支持键盘和明确标签。
9. 中文提交信息；每个独立需求结束时合并本需求内的临时提交，保留原提交信息；不修改此前无关历史。
10. 本规格本身不替代实施授权；本轮已获授权的 P0 实施可持续执行。真实账户配置／指令修改、插件授权、电脑操作或上线重启须另行明确授权。

## 4. 页面与交互

使用 `/settings?section=general|configuration|personalization|usage|plugins`；现有 `/settings` 默认进入常规，未知 section 回退常规。复用现有 history/popstate 导航，不引入路由库。

桌面使用设置侧栏，手机使用页面内可访问的分类选择。仅加载当前分类所需接口；用量沿用已有全局 provider。切换分类、浏览器后退和离开设置页时，有未保存配置／指令必须提示保存、放弃或取消，取消应留在原位置。完整关闭／刷新页只使用浏览器原生 beforeunload 提示。读取失败保留用户输入，不能用默认值覆盖草稿。

### 4.1 配置（P0）

允许写入的固定字段：`model`、`model_reasoning_effort`、`approval_policy`、`approvals_reviewer`、`sandbox_mode`、`sandbox_workspace_write.network_access`、`web_search`。不接收用户提供的 keyPath。

- 模型及强度使用现有模型目录动态校验；保存前验证二者兼容，不自动降低强度或替换模型。
- 审批方式优先复用 ask／auto-review／full-access 的现有语义。高级区允许受支持的审批、审核者、沙箱组合；映射固定、一次原子保存相关字段。
- 使用 `permissionChoices` 及 `configRequirements/read` 检查限制。遇到新版 `permissions/default_permissions`、granular 策略或其他无法无损表示的权限，显示原生自定义状态与原因，权限部分只读；不能把它改写成旧的三种预设。模型／搜索等独立受支持字段仍可修改。
- 网络选项仅在 workspace-write 下编辑；其他沙箱显示其实际语义，不把无效开关当成限制已生效。改变权限预设时保留未知键和无关写入根目录，不隐式扩大它们。
- 搜索值仅接受原生支持的 disabled／cached／live；受管约束禁止的值不可保存。
- 页面可选当前项目查看有效值，项目只能通过已有 projectId 解析。选择项目不会把保存位置改成项目文件。
- 每项显示：用户文件原值、当前上下文有效值、来源、是否可写、不能修改的原因。来源层只投影允许字段；不向浏览器返回 token、provider 密钥、MCP 环境变量或整份 config。
- 读取成功才给出用户配置文件路径和可用于写入的版本；选中 profile 或无法确定用户基础层时不猜测目标，禁用保存并说明。
- 保存发送读取时的版本；冲突返回 409，保留编辑值并要求重新读取、比较后再保存。一次批量写入后回读，分别报告“已写入”和“当前有效值”；项目覆盖不是写入失败。
- 结果未知时显示“保存结果待核实”，只允许先读回核对，不自动重复写入。
- P0 不启用 `reloadUserConfig`。统一提示“本机默认配置已保存，供后续新建／重新加载的会话读取；当前任务设置保持原状”。实际会话上的显式设置与项目覆盖仍可能优先。
- 现有 `/api/model-defaults` 保留 URL 和成功字段，升级为同一写入规则；首页在读取初始配置时取得用户层版本，创建任务后沿用该版本，不在保存前偷取新版来覆盖外部修改。无法取得版本或发生冲突时保留已创建任务及本地偏好，提示全局默认值未保存；不能因这个附属写入重发任务。旧前端缺版本返回可解释的 409，提示刷新页面，不作为无版本写入后门。

### 4.2 使用情况（P0）

将现有额度内容同时用于设置页与工具栏弹窗，共享 provider。保留额度窗口、剩余百分比、重置时间、最后成功读取时间、陈旧标记、刷新、重置机会及确认流程；账户变化时关闭旧账户确认，结果未知保持原幂等标识。未知值不显示为 0。

P0 不增加套餐购买、自动充值、历史消费分析，也不把聊天 token 数推算成官方剩余额度。

### 4.3 常规（P0）

- 保留版本、工作目录、CLI 来源、模型刷新、两个重启入口、通知、布局重置和密码修改。
- 增加诊断摘要：是否启用、最近成功写入时间、丢弃记录数、写入失败数；从当前 Diagnostics 实例读取，不扫描日志正文，不为读取状态启动原生进程。无诊断实例显示未启用。
- P0 只展示诊断状态；启用仍使用已授权的重启脚本流程，不另做绕开活动任务预检的开关。
- 增加此浏览器的桌面发送快捷键：Enter 发送／Ctrl+Enter 发送（macOS 对应 Cmd+Enter），Shift+Enter 始终换行，输入法合成中不发送；手机软键盘 Enter 保持换行。默认保持当前行为，只影响首页和会话主输入框。
- 新任务沿用上次模型／强度／权限继续使用现有存储；本页说明其范围，不另复制偏好值。排队／引导模式、终端、依赖重装不纳入 P0。

### 4.4 个性化（P0 的指令部分）

提供“个人 AGENTS.md”和“所选项目根 AGENTS.md”的文本查看、编辑、保存及保存前差异预览。个人路径依据当前原生初始化返回的 codexHome；项目路径依据 `Projects.resolve(projectId)`。没有可靠主机路径就禁用编辑，不能退回任意进程 HOME。

- 仅允许这两个固定目标，首期 UTF-8 文本上限 256 KiB，超限／无效编码只读并说明原因。
- 保留 BOM 和原有换行风格；新文件采用 UTF-8、LF。不存在的目标显示为空和“尚未创建”，GET 不创建文件。
- 读取返回文件版本，保存重新比对；并发编辑冲突返回 409，保留草稿。按目标串行处理本服务写入，同目录临时文件加原子替换，失败不得先删除原文件。
- 写入前核对真实父目录和目标类型，拒绝目标符号链接、目录联接逃逸及目标被替换为目录；测试临时目录，不操作真实个人指令。
- 差异预览使用原文／新文并排文本（手机上下排列）；已有 Git DiffView 需要 Git diff 数据，不为指令比较引入 diff 引擎。保存正文是原始文本，不经 Markdown 转换。
- 个人或项目存在 `AGENTS.override.md` 时显示覆盖提示与实际路径，只读提示，不代为修改。说明项目子目录指令也可能影响任务，本页不声称列出了全部有效指令。
- 保存不自动向活动任务插话；提示后续新会话读取。不开启、关闭或删除任何记忆。
- 文件版本比较和原子替换避免常见丢失修改及半写文件，但不是跨桌面端／编辑器的事务锁；文档保留这一限制，不能声称绝对跨进程 CAS。

### 4.5 已安装插件（P0，用户追加）

新增只读列表，优先验证 `plugin/installed`，只返回 `installed === true` 的条目，不请求推荐安装条目，不以目录存在推断已安装。

- 展示名称、描述、已安装状态、原生报告的启用状态、本地版本和来源名称；版本缺失显示未知，不能用市场最新版本冒充本地版本。
- 同名不同市场使用“市场标识＋插件 id”区分。未知 availability／disabledReason 保留为未知状态，不推断可用。
- 启用只表示原生配置状态，不代表 MCP 已连接、应用已授权或本会话工具可用；P0 不为了填这些字段额外触发登录、重连或逐插件详情调用。
- 名称搜索在已读取数据内进行，提供显式刷新和最后成功读取时间。刷新失败保留旧列表并标记待更新；部分市场失败展示可用部分及错误数量，不显示为完整结果。
- 无支持接口显示“当前 Codex 版本不支持读取已安装插件”；真实成功且结果为空才显示“暂无已安装插件”。不回退到开发中的 `plugin/list`，不扫描插件缓存目录填假数据。
- 不加载任意远程图标或输出原生完整对象；首期使用名称与占位图标，避免显示凭据、带认证参数的源地址和原生错误详情。
- P0 无启停开关、安装、卸载、OAuth、市场配置和技能编辑。后续逐项验证并作为 P1 独立需求。

## 5. 最小接口与模块边界

沿用既有 API 前缀、错误结构和鉴权层，不引入配置数据库、配置注册中心、通用文件写入或通用 RPC 转发。

| 接口 | 行为 |
| --- | --- |
| `GET /api/codex/settings?projectId=` | 允许字段、用户层版本、来源和当前项目有效值；能力失败保留明确错误 |
| `POST /api/codex/settings` | `{projectId?, expectedVersion, values}`；仅固定白名单，原子写入及回读 |
| `GET /api/codex/instructions?scope=user|project&projectId=` | 固定文件内容、版本、路径、覆盖提示；项目 scope 必须有 projectId |
| `POST /api/codex/instructions` | `{scope, projectId?, expectedVersion, content}`；固定文件受控写入 |
| `GET /api/codex/plugins?projectId=` | 已安装插件安全投影，包含 supported、partial、updatedAt 与结构化状态 |
| `GET /api/settings` | 保留旧字段，增加独立的诊断摘要；某一原生模块失败不清空整个设置页 |

读接口原生不支持使用结构化能力标记；实际读取失败用 503，写入结果未知用 504 与 `SETTINGS_WRITE_UNKNOWN`，版本冲突用 409，输入非法用 400。所有界面根据错误来源显示错误，不把配置／插件失败统一伪装成空结果。

P0 只新增具体的配置投影、指令文件服务和插件投影；原生进程生命周期仍归 Runtime 管。配置文件写入由原生 RPC 执行，个人／项目 AGENTS.md 由固定目标的文件服务执行。

## 7. 后续阶段与能力边界

P1 个性化先区分原生记忆的读取使用、生成、外部上下文参与规则；Agent Memory 插件独立管理，不能以同一开关删除两种记忆。删除记忆属于另外的明确授权操作。

P1 插件按详情与状态、启停、OAuth、安装卸载、市场的顺序拆分；每一步先证明当前 CLI 接口稳定性和写入后的生效范围。不要为等待市场能力延迟 P0 已安装列表。

电脑操控前置检查记录：主机平台、桌面会话、Web 启动身份、原生工具是否提供、浏览器扩展连接能否观测。不能用“配置 enabled”或工具类型存在替代实际发现成功。P2 的截屏、操作、授权持久化与撤销需要独立设计和明确验收；不在本轮接入远程桌面基础设施。

## 8. 资料与限制

- [官方 App Server 配置和插件接口](https://learn.chatgpt.com/docs/app-server)：配置读取／批量写入可复用；`plugin/list` 文档目前仍提示开发中，不作为 P0 依赖。
- [官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)：配置字段与记忆选项的语义。
- [官方设置说明](https://learn.chatgpt.com/docs/reference/settings)：自定义指令映射 AGENTS.md；桌面访问能力需单独验证。
- 本机 `.local/protocol/v2/ConfigBatchWriteParams.ts` 说明 `reloadUserConfig` 不热加载模型／强度等会话静态默认值。本规格进一步收敛为 P0 全部不热加载。
- 协议缓存和官方文档不能替代目标 CLI 的现场验证；不支持的能力必须明确展示，不进行未经确认的兼容猜测。
