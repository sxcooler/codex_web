# Codex 设置体验修订

## 目标与依据

依据用户提供的官方常规、配置、个性化、使用情况截图，修复当前表单堆叠、技术信息抢占主体和整页滚动的问题。主会话负责设计与计划；实施及 review 全部由 gpt-6.1-sol / high 子 agent 完成。继续使用已有 React、CSS、原生配置写入和差异查看器，不增加 UI 依赖。

## 页面与视觉设计

- 设置占满工作区剩余高度；桌面分类栏宽 190–220px，与右侧内容分别滚动。标题和分类切换不随内容消失；外层 workspace 不产生第二根整页滚动条。进入分类后内容滚回顶部。
- 分类分组：Codex（常规、配置、个性化、使用情况、已安装插件）和 Codex Web（独立一页）。现有路由与离开草稿保护继续工作。
- 右侧内容最大宽度 760px，在可用区域居中，桌面左右留白至少 28px，顶部 36px；手机边距 16px，分类选择固定在内容上方。窄屏卡片行允许控件换行，无水平溢出。
- 参照官方深灰底色与卡片：设置区域背景 #181818、卡片 #232323、细边框 #343434；主文字 #f2f2f2、次文字 #a1a1a1。圆角 14–16px，卡片内部行分隔线，组间 28–32px。标题 24px、行标题 14px、帮助 12–13px。设置页使用中性选中底色；不重做整个应用主题。
- 常用行：左侧标题和一句帮助，右侧紧凑下拉框或原生可访问开关。控制宽度自适应且不超过 240px；不要把所有下拉框拉成整页宽。
- 状态、错误与只读原因就近显示；不能靠颜色独自表达含义。默认不铺开实现路径、来源、JSON 或重复用户值。
- 明确保存的配置提供紧凑保存栏、已修改数量和放弃操作；保存成功/失败可感知。已有版本冲突、未知结果、草稿保护不得弱化。

## 各页内容

### 常规

发送快捷键保留，浏览器偏好立即保存并有失败提示。增加原生“速度”：标准对应 service_tier=default，附加速度从当前模型 serviceTiers 获取（当前 priority/Fast），不能拿推理强度冒充速度或硬编码 fast。速度采用已有带版本配置写入，只影响后续读取默认配置的会话；保持当前运行任务不变。

### 配置

分组为“模型”“权限与网络”。模型/推理强度、权限预设、审批策略、审核者、沙箱、网络、网页搜索保留真实功能并使用中文选项；高级审批组合可折叠，但必须能发现。项目上下文选择放在页首紧凑工具行，清楚标明保存到主机默认配置。来源、用户原值、有效值与配置路径收进“配置详情”，有覆盖/只读时在对应行提示。保留保存前变更比较，无需每一行重复完整元数据。

### 个性化

默认展示“Codex 记忆”卡片与“自定义指令”入口。原生记忆与 AgentMemory 插件分开：features.memories 总开关；生成记忆与使用记忆两项高级开关；“允许从工具聊天生成记忆”反转映射 memories.disable_on_external_context（范围为 MCP / 网页搜索 / 工具搜索）。未显式配置的官方默认值必须与“未配置/未知”区分，不能把 null 当 false。开关保存复用 native CAS；受管限制只读。当前协议没有删除所有记忆接口，不显示可点击的假删除按钮，简短说明在官方客户端管理即可。

“编辑指令”进入同分类的指令编辑视图，返回经过已有离开保护；避免记忆和指令表单竞争同一个 DraftActions。保留个人/项目固定 AGENTS.md 编辑、冲突核对。修改对比复用 GitHistory.DiffView 的行号、红绿新增删除与 split 结构；左右共用滚动容器天然联动，窄屏 unified。大输入不能引入无界二次方 diff；复用现有 diff 构建能力或有明确资源上界的实现。不可为了预览把用户指令写进真实文件。

### 使用情况

顺序为套餐周期用量、额度余额、重置机会。展示原生 codex credits.balance，如 62,500；不推导币种，不转浮点，不对不同桶余额求和。零、未知、无限分别表达；单桶/多桶兼容、刷新失败和账号切换不能展示错误账号余额。复用同一 AccountUsageProvider，快捷用量弹层同步获得余额。保留重置机会的独立确认/幂等保护；没有原生接口的购买/自动充值不做假控件。

### 已安装插件

沿用只读能力和搜索，列表改为紧凑行：名称、简短说明、明确启用状态；版本、市场、ID、可用性细节默认折叠。不可把配置启用宣称为本会话工具已连接。

### Codex Web

独立承载会话列表排序、通知、布局重置、管理员密码、运行状态和诊断维护。运行状态用整齐信息行和低噪音状态文字；详细路径与原始诊断收起，按钮/成功提示有独立间距。重启确认及 90 秒安全检查保持不变。发送快捷键仍归常规，因为官方也有此类别。

会话排序为浏览器偏好：默认“更新时间”，另可选“创建时间”；保存即刷新左栏，刷新/分页/归档/隐藏请求均携带相同排序，收藏仍置顶。同排序内按原生时间降序，稳定处理相同时间。排序变化废弃旧请求和 cursor，不混入不同顺序的分页结果。

## 分支列表修复

用户案例 00000000-0000-4000-8000-000000000105 已持久化且未隐藏、未归档。只读取证确认 native thread/list 过滤空 preview，排序不是根因。成功创建的 Web fork 必须在列表可见，刷新和重启后仍可见；利用 Web 元数据登记及原生只读 header 补齐，不向 fork 发送虚假消息、不改原生 SQLite/JSONL。既有受影响分支通过已打开记录或受控迁移恢复。正常原生条目与补入条目按 ID 去重；隐藏、归档、子 agent 排除、普通列表分页/排序语义继续成立。补充查询有明确上界，不给每个历史会话增加串行 RPC；无法验证时不能编造可用状态。

补充仅针对最新原生 header.preview 为空的已登记 fork；已有原生预览后交回普通原生分页。已登记 fork 用不可变序号分页，每次最多核查 32 条、并发最多 4，短总预算防止拖慢正常列表；32 不是总数量上限。复合游标独立保留原生和登记位置，两者耗尽后才结束加载。已载入条目统一按选定原生时间排序去重；大量空分支需继续加载，后续取得的真实时间可能让条目插入已载入列表中，因此显示补充仍未读完的状态，不能宣称首屏包含尚未读取候选的全局时间顺序。这避免为原生过滤缺陷额外建立全历史快照系统。

## 验收

- 桌面长配置与 Codex Web 页滚动，分类栏位置不变；手机 390px 分类可达、无横向溢出；1440/900 与官方参考做可见效果对照。
- 速度、记忆 CAS 写入和受管约束；credits 真实投影与未知/无限/零、大字符串；不会消费额度或自动充值。
- 配置草稿跨分类、项目、返回/前进依然受保护；指令差异红绿、行号、共享滚动及手机 unified。
- fork 成功即出现，后续刷新不消失，不重发原生 fork；排序切换持久化，首屏和下一页一致，旧响应不能覆盖新选择。
- 浏览器桥失败另做只读归因，不因推测重启服务。用户已同意用 Playwright 本机 Chrome 验证本改版。

## 能力证据与边界（2026-10-07）

- CLI 0.159.2 当前生成协议 Model 包含 serviceTiers/defaultServiceTier；Config 有 service_tier；NewThreadModelDefaults 可约束 serviceTier。真实主机只读 config/read 返回 default。
- 原生记忆键及默认来自官方 [配置参考](https://learn.chatgpt.com/docs/config-file/config-reference) 和 [schema](https://learn.chatgpt.com/docs/config-schema.json)，CLI strict-config 只读启动覆盖验证 generate_memories/use_memories 可识别。features.memories 与 featureRequirements 均为既有原生接口字段；没有找到删除全部记忆 RPC。
- 真实主机 account/rateLimits/read 的 Codex credits 返回有限余额，RateLimitSnapshot/CreditsSnapshot 定义 balance 为字符串。当前 Web bucket() 丢失该字段，属于投影遗漏。
- native thread/list 的空 preview 过滤由真实分页与本机原生数据库只读计数交叉核对；Thread 没有 archived 字段，当前版本真实归档 header.path 位于 codexHome/archived_sessions。此路径分类是兼容性边界，未知布局必须不补入而非猜测。
- 浏览器只读归因：10:46 Web 重启成功；11:19 IAB 实际创建且 dom-ready，但工具返回超时；11:23 Desktop 窗口销毁后 IAB 退注册；11:27 工具只发现 Chrome，Chrome/遥测 fetch 仍失败。Web 进程持续存活，尚无证据把早先工具返回超时或 Chrome 失败归因于 Web 重启。不执行推测性重启。
