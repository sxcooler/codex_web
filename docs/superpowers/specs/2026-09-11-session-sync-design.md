# 会话增量同步设计

用户确认：先落文档再实施；完成后重新生成便携包与干净源码包。

## 目标与范围

首次进入或无法续传时加载会话快照，运行中通过 SSE 接收消息和状态增量。已完成历史不随每次文本输出重读或重传。保留外部客户端状态校正、手动刷新、审批、插话、附件、释放和重连能力。不新增依赖，不改变原生任务的执行语义。

## 同步契约

- 快照继续使用 GET /api/sessions/:id，增加同步水位 syncCursor。水位必须与快照的基线一致。
- SSE change 使用既有 id/threadId/kind，增加 revision 和 patch。patch 可包含 state（phase、activeTurnId、pending、error、permissions、retry、release、model）、thread（不含 turns 的头字段）、turn（按 id 合并）、item（{turnId,item} 替换）、delta（{turnId,itemId,field,offset,text}，field 仅 text 或 aggregatedOutput）。未变化的旧轮次和旧输出不进入文本增量事件。
- 每个会话 revision 连续，客户端丢弃重复/旧事件。轮次和消息按 id 合并；终态优先，文本增量使用 UTF-16 偏移量校验，已含有的文本不追加第二次，缺口触发重新同步。
- 首次快照与 SSE 建连之间用 syncCursor 续传；快照加载期间先断开旧流，完成后以该水位重连。原生 EventSource 重连使用 Last-Event-ID；主动建连可通过受校验的 cursor 查询参数续传。
- 回放缓冲按字节限制；过期游标、运行时重启、不能表达的变化或超大事件发送 resync。心跳和 ready 不再触发完整历史请求。
- 手动刷新执行权威快照；正常发送/审批响应不重建 SSE。定期轻量状态校验覆盖其他客户端工作及漏失终态，必要时才重新读取变化轮次。缓存不可使发送权限校验依赖过时状态。

## 缓存与边界

复用 Runtime 的 liveTurns；已完成正文复用浏览器已有历史；服务端仅缓存头字段和轮次签名，全局最多 8MiB，超限逐出后要求重新同步。权威全量快照仍重新读取原生历史，避免外部客户端改写后读到旧内容。状态检查不读取消息 items 分页，禁止用 UI 缓存绕过运行状态检查。额外历史分页 UI 不在本轮范围。

## 验收

长对话接收连续文本增量时，全量会话 GET 数量不随增量次数增长，增量不包含旧命令输出；终态历史不反复请求原生 items 分页。覆盖重复事件、断线回放、游标过期、运行时换代、快照/增量交错、最终消息替换、审批结束、原文复制、乐观消息去重与附件。运行全量测试、构建及真实浏览器模拟 API 验证，随后打包并校验解压运行与归档内容。

## 用户补充

左侧会话更多菜单点击外部空白处关闭，菜单内部操作保持可用；使用原生 details 和全局 pointerdown 监听，无额外弹层依赖。

## 实施结果与实际边界

- 新增 `GET /api/sessions/:id/status?epoch=…`，返回 `{resync:boolean}`。每 30 秒及页面重新可见时校验原生头/轮次状态，正常输出不读取历史正文。空会话沿用同 epoch 的未持久化兼容分支。
- 快照在原生分页读取期间记录变化，合并终态和缺失消息后给出一致的 revision/syncCursor；原生已有的终态消息保留权威替换。活动原生正文用于初始化后续 delta 偏移。
- SSE 回放沿用 64KiB 总字节上限；单个补丁超过上限转换成 resync。内部快照补齐仍保留大终态内容。游标过期、换代、缺口及超大事件才重载基线。
- 插话受理后仅分页当前轮次，根据 clientId 找到原生用户消息并发布补丁；无法确认时回退重新同步，不伪造原生消息 ID。带附件发送后一次权威刷新补齐附件预览。
- 消息组件使用 React.memo，未变化的历史对象保持引用，避免每次增量重复渲染旧命令输出。
- 同步前后不更改运行中任务权限或发送验证。新后端协议需要服务重启后生效，本轮未中断现有服务。
