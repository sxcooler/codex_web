# 公开发布隐私检查

## 历史扫描范围与结果

以下保留迁移前公开版本的审查记录，原文未单列扫描日期；不表示本轮新增文件已完成最终归档审查。检查覆盖当时 Git 跟踪的文档、源码、脚本、测试、锁文件和静态资源，以及 `git rev-list --objects --all` 可达的提交、树清单和文件对象。检查项目包括个人用户名和绝对路径、设备与私网域名、项目名称、Thread/Turn 标识、邮箱、常见密钥格式及凭据赋值候选。

当前文件中的个人环境示例已泛化；测试中的会话标识使用合成 UUID，测试邮箱和固定测试密码只用于隔离 fixture。私网地址段判断、协议字段、依赖完整性散列和公共文档链接属于正常代码与依赖数据。检查没有发现已确认的真实 API 密钥或私钥。

`.local/`、原生 Codex 用户目录、认证文件、数据库、附件、日志、未脱敏截图、测试输出和旧 `.git` 均不得进入发布物。`docs/assets/screenshots/` 仅存放人工核对后的脱敏展示图，可随文档发布；原始截图留在忽略目录中。忽略目录只核对排除规则，不读取、删除或迁移其中的凭据。运行包和源码包应按明确文件清单导出，打包后还需复查归档目录及文本内容。

## 迁移前原仓库历史的限制

当时检查的旧 Git 对象和提交身份仍含个人环境记录。清理当前文件或 squash 提交不会移除祖先提交、其他分支及标签可达的内容；该原仓库历史应继续留在本地，不应直接推送或加入压缩包。此历史结论不自动适用于从干净源码重新初始化的新仓库，新仓库按自己的实际内容检查。

上述结论对应迁移前审查。2026-09-13 已按用户要求从本地历史移除两份隐私归档及其旧来源文件；发布前复查待推送 master 的可达对象，确认目标路径和旧文件对象不存在，已知个人设备路径、私网主机标识及常见凭据格式规则无命中。Git 提交身份仍作为正常版本元数据保留。本次复查不代表任意格式的秘密都可被自动识别。

## 限制

本次属于本地规则扫描和人工上下文核对，不能证明不存在任意格式的秘密。没有扫描远端仓库、reflog、不可达对象、无关用户数据或原生聊天历史；也未对二进制内容做 OCR 或隐写检查。新增文件、重新构建和新增依赖都可能改变发布内容，因此本说明不替代最终归档复查。私有明细仅保存在被忽略的本地审计报告中，公开报告不记录发现值。


## 源码包发布流程

按 [便携构建指南](portable.md#构建) 导出干净源码，核对包含 README.md、README_EN.md 和当前 docs 分类目录；WSL 测试环境、认证、日志和原生历史不进入源码包。检查归档文件清单及文本后，可在全新目录解压、初始化 Git 并配置自己的提交身份；发布已有仓库时应单独检查准备推送的历史，不能把源码包检查结果直接用于证明 Git 历史安全。

## Windows / Linux 发布物

在已提交的同一版本上分别原生构建 Windows x64 ZIP、Linux x64 glibc tar.gz 和两个平台的应用更新 ZIP，选取一份通用源码 ZIP。对全新解压包执行产物检查并设置 `PORTABLE_TEST_UPDATE` 验证在线升级，确认 `manifest.json` 的 `sourceCommit` 与发布提交一致。核对归档排除项后汇总五个压缩包的 `SHA256SUMS.txt`，随版本标签一起上传 GitHub Release；不要上传已启动过的测试目录。
