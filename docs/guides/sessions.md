# 会话打开、刷新与释放

会话历史属于原生 Codex Thread；浏览器页面、实时连接和运行中的任务分别管理。协议与实现边界见 [会话工作区](../design/session-workspace.md) 和 [增量同步](../design/session-sync.md)；释放与归档是不同操作。

## 用户流程

原生只读接口返回 `notLoaded` 时，仅表示当前 Web 运行时未加载会话，不能据此判断其他客户端是否占用。现在点击会话或手动刷新/重试时，会先用原生 resume 核对写入占用，成功由 Web 持有；冲突时在输入区提前显示“已在另一个应用中打开”，历史仍可读，发送禁用。普通历史读取不能清除此锁提示，需对方释放后显式重试。检测不发送模型消息、不强制抢占。参见[工作区补充设计](../design/workspace-panels.md)及[官方读取/恢复说明](https://learn.chatgpt.com/docs/app-server#read-a-stored-thread-without-resuming)。

1. **打开网页或返回网页**：读取最近会话；打开的会话重新读取原生历史与状态。页面恢复、获得焦点和网络恢复也会触发同步，无需退出重登。
2. **刷新最近会话**：重读第一页并重置分页，使 VS Code 新建或归档的会话变化可见；失败时保留已有列表并提示错误。
3. **刷新当前会话**：重新核对占用、重建实时连接并读取历史及状态；检查与读取分别设 30 秒上限，在途请求合并。检查失败仍读取历史并提供重试；检查期间暂停发送。
4. **继续会话**：重新打开已释放的 Thread 时核对占用并恢复，继续原有历史。就绪后可发送；单纯打开或刷新不会发送消息。
5. **中止**：仅中止当前 Web 管理的活动任务，等待原生终态后才能继续或释放。
6. **释放并关闭**：空闲时释放成功才返回新任务页，关闭当前实时订阅。有草稿时先确认是否丢弃；失败则留在原页并显示错误。已持久化会话仍可从最近会话打开。
7. **跨客户端接力**：即使其他应用未运行任务，只要仍持有 writer，打开会话也会显示占用提示。对方关闭/释放后点击“重试”，确认恢复再发送；不会强行抢占。
8. **归档与恢复**：会话菜单的“归档会话”操作原生历史，成功后移出最近列表；当前会话同时关闭。有活动任务、待审批或其他客户端占用时拒绝归档。切换列表范围到“已归档”，从菜单“恢复归档”回到最近会话。“从 Web 隐藏”仍只改变本 Web 偏好。归档前确认清除草稿；失败保留当前内容，结果未知时刷新核对，不自动重试。

## 状态与按钮

“已连接”只表示实时通道已建立，不能据此判断任务是否完成。

| 会话状态 | 发送 | 中止 | 释放并关闭 |
| --- | --- | --- | --- |
| 就绪 / 已释放，可继续 | 可以 | 不可用 | 可以 |
| Web 运行中 / 等待审批或输入 | 等待本轮结束 | 可以 | 不可用 |
| 其他客户端占用 | 不可用 | 不可用 | 不可用 |
| 状态待核实 / 同步失败 | 先刷新核对 | 已知有 Web 活动任务时可用 | 不可用 |

审批与输入通过对应交互卡片处理。提交结果未知时保留草稿，并要求用户核对历史后显式解锁重试；刷新和重连不会自动重发。

## 历史与数据边界

同步以原生最新历史为准，状态待核实或失败时先刷新，不根据“已连接”推断任务结束。释放不归档、不删除历史；归档及恢复使用原生接口，可与其他 Codex 客户端共享。运行时切换造成的只读历史错误自动重试一次，持续失败保留刷新入口；消息和归档不会自动重发。

用户消息块和头像靠右，正文保持左对齐。角色名称内侧显示可用的本轮时间：首条用户消息对应原生 `startedAt`，最后一条 Codex 回复对应 `completedAt`。时间按浏览器本地时区显示，悬停查看完整值和“本轮开始/完成”说明。原生没有逐条消息时间时，不为插话、中间回复或缺失时间的旧历史猜测发送时间。

当前 CLI 的空会话在首条消息前可能尚未落盘，释放或运行时退出后无法找回；页面保留提示。未发送草稿不跨浏览器关闭保存。同步实现与状态校正规则见 [会话工作区](../design/session-workspace.md#状态同步的补充边界) 和 [增量同步](../design/session-sync.md)。

## 回归检查

运行 `npm test` 与 `npm run build`。运行 `npm run dev` 后，在浏览器打开 `/tests/session-lifecycle.html`、`/tests/recent-sessions.html` 与 `/tests/interaction-followup.html`；检查页使用模拟 API，不消耗模型额度、不改变真实会话。

后端覆盖 writer 冲突后恢复、释放后保留历史继续、漏失完成、分页完成窗口、并发读取及发送保护。页面检查覆盖恢复事件、挂起读取重试、释放后发送、失败留页与草稿保护。真实 VS Code 持有 writer 时仍会拒绝接力，不能把模拟检查视为所有客户端版本的兼容性保证。

## 自动释放与草稿

离开会话、切换会话或打开新任务自动请求释放；活动任务和待审批保留，终态后继续释放。返回时取消尚未执行的释放，并等待已经在途的释放完成。浏览器按会话串行处理离开与返回，刷新、聚焦和重连均等待返回确认，避免快速往返造成错误释放。

同一 Web 服务进程内，显式选择的权限会在自动释放、空闲退出及重连后保留，并重新核对原生权限限制。手动“释放并关闭”会清除这项选择，供其他客户端接力；Web 服务重启后也重新采用原生配置。

旧会话不支持逐项历史接口时，改为每页读取一个完整轮次，保留历史翻页和完整命令输出；不会修改原生会话文件或自动重发消息。

手动“释放并关闭”只有在后端确认 handoffReady 后导航；未完成则留在当前页并显示原因。SSE 超过 45 秒没有有效事件时重连，重读历史不会重发用户消息。原生 willRetry 单独显示为 Codex 重试。

未发送的草稿、选项、附件及阅读位置在本次浏览器页面生命周期内保留；新建任务草稿同时保留项目/Clone上下文。完整刷新仅保证布局比例恢复，草稿未持久化到磁盘。已接受的附件通过私有数据库与文件目录持续保留。

本节是第二阶段实现说明；真实 VS Code 往返与手机通知尚未重新验收，见 [实施验收](../verification/2026-09-11-phase2.md)。

## 设置与生效范围

P0 设置页提供常规、配置、个性化、使用情况、插件五类，可用 `/settings?section=general|configuration|personalization|usage|plugins` 直接打开；`/settings` 和未知分类回到常规。此处说明已实现的工作树行为，线上部署与真实写入另行验收，见 [设置能力与验收记录](../verification/codex-settings-capabilities.md)。

| 设置范围 | 保存位置与影响 |
| --- | --- |
| 此浏览器 | 桌面 Enter／Ctrl+Enter（macOS Cmd+Enter）发送偏好只在当前浏览器保存；Shift+Enter、输入法合成及手机 Enter 不发送。首页与会话主输入框共用偏好。新任务模型／强度／权限沿用既有浏览器偏好 |
| 主机默认配置 | 配置页显式保存固定支持字段到服务器主机的用户配置；首页创建成功后的模型默认值保存沿用同一版本检查与回读规则。首页默认值保存失败不重发已创建任务 |
| 项目有效配置 | 选择项目仅查看该上下文的有效值和来源；用户值与项目覆盖后的有效值分别显示，保存位置仍是主机用户配置。P0 不编辑项目 config.toml |
| 当前会话 | 显式会话选项继续由会话入口管理。保存主机默认值不静默改变当前任务，不热加载、不自动重启；后续新建／重新加载的会话读取默认值，项目覆盖与会话显式设置仍可能优先 |

配置、指令和发送偏好均先编辑后保存。版本冲突保留草稿，重新读取并比较后再保存；配置写入结果未知时先回读核对，不自动第二次写入。分类切换、侧栏跳转、后退及显式退出受未保存提示保护，可保存、放弃或取消；刷新／关闭使用浏览器原生提示。

个性化只编辑原生初始化定位的个人 AGENTS.md 或所选项目根 AGENTS.md。保存前显示原文／新文；保留原 BOM 与换行，限 UTF-8 256 KiB。AGENTS.override.md 只显示覆盖提示，子目录指令也可能影响任务；本页不列出全部有效指令。版本复查和原子替换减少丢失修改，但不是跨编辑器的事务锁。保存不会向活动任务插话，后续新会话读取。

使用情况与工具栏额度弹窗共享请求和状态；未知用量不显示为零，重置机会继续要求显式确认。插件页仅列原生报告的已安装项：启用状态不代表连接、授权或当前会话可调用，本地版本未知不借用市场版本。接口不支持、空列表、部分市场失败和刷新失败分别显示；P0 不提供插件管理写操作。

常规页保留版本、目录、模型刷新、通知、布局重置、密码和既有重启入口。诊断摘要只读取当前服务实例的启用状态、最近成功写入和丢弃／失败计数，不扫描旧日志、不为该摘要启动原生进程；原生权限与账户在此摘要中可能仍是未知，应到配置与使用情况核对。查看设置不授权电脑操控。

## 回答分支与引用的记忆

已完成轮次的最后一条普通 Codex 回答，在复制 Markdown 旁提供“分支到新聊天”。分支继承至该轮（含该轮）的原生上下文和原项目目录，后续轮次不进入新聊天。点击只创建会话，不发送消息，也不回滚项目文件。创建成功即打开返回的新 ID；最近会话刷新失败不影响打开。源会话的未发送草稿按已有页面生命周期机制保留。

明确失败留在源页面，可点击“重试分支”。超时、断连或响应异常显示“分支结果待核实”，先核对会话列表，页面不会自动重发。已知部分成功提供“打开已创建的会话”，避免重复创建。离开页面后返回的结果不会强行跳转；返回源会话仍可打开已知新 ID。分支状态和草稿一样只在本次浏览器页面生命周期保留，完整刷新或退出登录后不保留。后端同请求幂等只限当前服务进程，不承诺跨重启只创建一次。

回答原生数据包含有效 `memoryCitation.entries` 时，已完成回答显示“引用的记忆”。小面板只展示摘要、来源路径和行号，支持 Enter 打开、Escape 关闭并还原焦点、点击外部关闭。无引用或全部记录无效时隐藏，生成中不展示未完成引用。路径和摘要以安全文本展示，不读取来源文件，不扫描记忆或插件，不根据字段猜测由哪个插件生成。

本轮工作树验收使用生成协议、真实 Runtime + fake native peer、模拟 API 浏览器 fixture；未对用户现有会话执行真实 fork，未部署在线服务。验收记录见 [回答操作设计](../superpowers/specs/2026-10-07-message-actions.md)。
